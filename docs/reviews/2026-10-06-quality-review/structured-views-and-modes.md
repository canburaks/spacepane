# Structured views and modes review — 2026-10-06

Reviewed from source only, on Linux, on 2026-10-06. Nothing was compiled, run, rendered or measured; every runtime statement below is inferred from code and from the repository's validation records, and says so. The dimension covers the mode vocabulary, its order and keyboard access; the outline that serves JSON, JSONC, YAML, TOML, INI, XML, property lists, JSON Lines records, summaries and cues; the table that serves CSV/TSV, the Profile, the Files listing, data summaries and the SQLite schema grid; the folder Tree; and the filter, sort, copy, path, tooltip, count and limit behaviour they share (decision 026's `ux-modes-structure` workstream and the data cluster's recommendations). Verdict: the views are native, bounded and privacy-correct, with good filtering, typed CSV sorting and live-reload state in the outline, but the mode control misorders 44 formats and mislabels 35, the models throw away the type and risk facts a world-class structured view needs, the grid, tree and outline behave three different ways, and four defects in shipped behaviour (one of them an honesty violation) should be fixed before any polish.

## Current state

Strengths to preserve:

- **Privacy is structural, not per-view.** Every outline, table, tree, profile, tooltip and copy is derived from the concealed presentation text, never from source bytes (`SafePreviewModes.swift:149-235`, `SafeListing.swift:42-63`, `SafeDataProfile.swift:4-15`). Copy paths are all concealed: outline rows (`NativeOutlinePreviewView.swift:164-169,362-400`), table rows (`NativeTablePreviewView.swift:441-446`), tree rows (`NativeListingTreeView.swift:277-284`), Copy All (`NativePreviewView+Interaction.swift:126-130`), accessibility custom actions (`NativeOutlinePreviewView.swift:156-161`). The Profile refuses to describe a column holding the concealment token (`SafeDataProfile.swift:108-116`), and a concealed CSV cell keeps a column textual so sorting cannot leak order (`SafeTableColumnTypes.swift:5-8`).
- **Exactness.** JSON numbers keep their lexeme (`SafeStructuredText.swift:96-100`), CSV cells are never reinterpreted (`SafeDelimitedTable.swift:4-6`), invalidation compares code units (`SafeTable ==`, `SafeOutlineNode ==`), and app-owned numbers are locale-formatted while file values are not (`SafeListingFiles.swift:5-32`, `SafeSchemaLabels.swift:80-86`).
- **Bounded everywhere** with explicit caps: outline 256 Ki UTF-16 units, 20,000 nodes, depth 64; table 20,000 rows, 64 columns, 500,000 cells, 4,096 units per cell; listing 20,000 entries, tree 60,000 nodes (`SafeDelimitedTable.swift:97-107`, `SafeListing.swift:31-32`, `SafeListingTree.swift:44-46`).
- **Good interaction primitives.** A literal, folded, bounded filter with ancestor context and next/previous match (`OutlineFilter.swift`, `NativeOutlinePreviewView.swift:171-244`); stable sort with blanks last and strict typed number/date columns (`SafeTableOrdering.swift:10-33`); selection that follows rows through sort and filter (`NativeTablePreviewView.swift:396-409`); live reload that keeps an outline's expansion, selection and filter (`NativeOutlinePreviewView.swift:88-103`); JSONPath copy with RFC 9535 escaping (`OutlinePath.swift`); a lazily computed Profile (`SafeDataProfilePresentation.swift:214-240`); honest "At least" bounds in the Tree (`SafeListingTree.swift:131-161`).
- **Accessibility groundwork.** Table cells carry their column title as label and a spoken alternative for sparklines (`NativeTablePreviewView.swift:220-224`); sorting is announced (:428-435); outline filter results, including "No matches", are announced (`NativePreviewView+Interaction.swift:223-226`); row copy commands are VoiceOver actions.
- **Tests are characterization-grade**: 20 listing view tests, 18 ordering tests, 17 filter/copy tests, profile and table accessibility tests; the 20,000-row filter and sort have loose Debug bounds.

**SV1 (Blocker): a limit notice that overstates completeness.** Every table cut by rows, columns or cell length shows `preview.table.truncated`, which ends "Source shows the complete concealed text" (`NativeTablePreviewView.swift:151-156`, `en.lproj/Localizable.strings:814`). That is true for CSV/TSV, where Source is the file's concealed text. It is false for every data-summary table (Parquet, Avro, Arrow, NumPy, NPZ, HAR: truncation comes from the adapter's `truncated` flag, `SafeDataPresentation.swift:94-95`) and for the SQLite schema grid (300-row cap, `SQLiteInspectionAdapter.swift:176`), because their Source is the adapter's JSON summary holding exactly the same bounded rows. A user told to look in Source for the rest finds the same rows. This breaks the honesty rule (decision 026 gate 12, AGENTS "never promise previews for missing bytes"). Fix: give `SafeTable` an origin and pick one of two sentences; for data summaries say only that the preview read the first rows. Effort S, 14-language string change.

**SV2 (Major): order and vocabulary.** `available` always starts with Source (`SafePreviewModes.swift:98`), so for 44 formats the opening view is segment 2, 3 or 4 (Parquet opens on segment 4 of Source, Summary, Table, Rows). "Source" names generated text for 35 formats: summary JSON for archives, folders, packages, SQLite, MIDI, data formats and comics; converted text for EPUB, FB2 and web archives; normalized JSON for property lists and normalized first-page XML for draw.io, with no notice. Several translations make it worse: "Código fuente" (es) and "源码" (zh-Hans) mean source code, "Исходный текст" (ru) original text. Users comparing a ZIP's "Source" with a JSON file's "Source" learn the word means nothing. Decision 026 gate 6 requires the default first and no "Source" for app-made summaries. The design that keeps tests and persisted state intact is in Recommendations (R2); nothing persists a mode or a segment index.

**SV3 (Major): the mode control is unreachable without a pointer.** The control is added after the scroll view (`NativePreviewView.swift:127,147`), has no accessibility label (no `setAccessibilityLabel` anywhere for it), and `PreviewShortcut` rejects any Option combination (`PreviewShortcut.swift:15`). A segmented control is in the Tab loop only when the user has turned on Full Keyboard Access, so for most keyboard and VoiceOver users there is no way to reach Table, Files or Outline at all. The self-audit rated P8 "minor"; it removes access to most of the product's views, so Major. Needs a Mac to confirm the Tab loop inside Quick Look.

**SV4 (Major): YAML outlines can be wrong.** When a sequence item is indented like its key (`exclude_paths:` then `- "dist/*"`, valid YAML and common), line 50 pops the key and line 56 names the item `[n]` among the roots: the outline shows `exclude_paths` empty and the item as a top-level row `[3]`. The type's own contract says unsupported forms return nil "rather than guessing a structure" (`SafeConfigurationOutline.swift:4-6`). In the port, 55 of the 287 YAML files that produced an outline (one per basename) show this signature (two inspected by hand: a `.codeclimate.yml` and a `.bandit.yml`). It also weakens the owner decision on YAML opening in Outline. Fix: when a `- ` line has the same indent as an open key with an empty value and no children, attach it to that key; otherwise return nil. Add both cases to `SafeStructuredTextTests`.

**SV5 (Major): the default listing view hides what the analyzer found.** Archives write per-entry `risks` and `encrypted` (`ContainerSupport.swift:207-218`), but `SafeListing.parse` never reads `risks` (`SafeListing.swift:42-63`), the Files row is path, kind, size and date (`SafeListingFiles.swift:49-54`) and the Tree shows a name with one of four generic symbols (`NativeListingTreeView.swift:205-214,264-271`), so `isEncrypted`, which both models carry, is never drawn. Names are drawn as decoded: a right-to-left override in an entry name (the analyzer's `directionalName`, `ArchiveRiskAnalyzer.swift:62`) reorders the visible name in Files and Tree, so `report<U+202E>fdp.app` reads as a PDF, while only the Summary outline marks the entry (`SafeSchemaLabels.swift:63-67`) and the findings banner gives a count without saying which. Hidden and inaccessible counts written by the folder adapter (`FolderSummaryAdapter.swift:36-43`) are visible only in Summary. The folders cluster asks for per-entry lock badges (folders report rec. 2); this is also the "verdict before content" principle. Fix in R4.

**SV6 (Major): wrong spoken data in the Profile.** `configure` reads the cell through `order[row]` but the spoken description through the display `row` (`NativeTablePreviewView.swift:213-224`), while the Profile keys descriptions by source row (`SafeDataProfilePresentation.swift:58,63,73`). The Profile is sortable and filterable, so after one header click VoiceOver reads another column's distribution or common values, and cells that have one read none. No test sorts a described table (`NativeTablePreviewViewTests.swift:260-295`). One-line fix plus a regression test.

**SV7 (Major): untyped outline rows.** `SafeOutlineNode` has no kind (`SafeStructuredText.swift:4-15`); the scanner reduces every scalar to a string (:96-100), so the view cannot show a type glyph, dim `null`, tell `true` from `"true"`, or say "{8 keys}". Containers show `{…}`/`[…]` in JSON and nothing in YAML, TOML and XML; duplicate keys are marked only by a hover tooltip and accessibility help (`NativeOutlinePreviewView.swift:150-154`), although doc 05:151 asks for duplicate-key warnings. This is the data cluster's second recommendation and decision 026's "type glyphs and counts". The change is renderer-local (R3).

**SV8 (Major): three views, three behaviours.** Filter: the outline trims whitespace and cuts at 256 UTF-16 units (`OutlineFilter.swift:16-18`); the table does not trim and cuts at 256 characters (`SafeTableOrdering.swift:51`), so a single space filters a table but clears an outline, contrary to decision 021:85 ("reuse `OutlineFilterQuery`"); the Tree has no filter. Keyboard: Command-F and Command-G reach a table only when it is already focused (above). Announcements: outline counts, including zero, are spoken; table results never are (`NativeTablePreviewView.swift:396-420`). - **Typical sizes fit.** In the 843-file JSON census, 91.6 % fit the outline caps; median 2.4 KB, p90 67 KB, p99 415 KB.
- **Observed working in Finder**: Source, Outline, Source in the Space-bar panel with disclosure (`native-renderer-performance-2026-10-04.md:174`).

Against, or not yet:

- **Size-dependent default.** No outline above 256 Ki UTF-16 units or 20,000 nodes (`SafeStructuredText.swift:31-35`); 2.4 % of the census fits the 1 MiB input budget but not the outline, and would open in Source with "Structured view is unavailable".

- **XML outline loses information**: attribute order (sorted), comments, processing instructions, mixed-content positions; any DOCTYPE disables it (`SafeXMLDocument.swift:7-8,36`); its copied paths are JSONPath (SV11).

JSON Loupe and QLook JSON open on a pretty source view, per the data cluster report.
- **Evidence gaps.** The Finder matrix reports "structured view unavailable" for a flat three-line YAML fixture (`finder-matrix-2026-10-04.md:38`) that the current parser accepts in the port: re-run before deciding. Whether an outline holding focus takes Finder's arrow-key file navigation is unverified (`interaction-2026-10-05.md:38`).
