# Thumbnails review — 2026-10-06

Reviewed from source only, on Linux, on 2026-10-06. Nothing was compiled, run, rendered or measured; every statement about Finder, Quick Look, caches or timing comes from the repository's validation records or from Apple's documentation, and is marked as such. The dimension covers the thumbnail extension, the `PreviewThumbnails` module, the catalog's thumbnail policies and the manifests derived from them, the companion's content-thumbnail switch, drawing at Finder's sizes, privacy and caches, time and memory bounds, concurrency, the pending 3D question and the tests. The verdict: the privacy engineering (policy before parsing, concealed-only input, whole-document withholding, counting tests) is careful and well tested, but no SpacePane thumbnail has been seen in Finder, none carries a type, eight of the 41 "content" formats draw an app-made summary instead of the document, and 31 types trade an informative system icon for one type-less glyph.

### One request, end to end

1. `ThumbnailProvider.provideThumbnail` validates the geometry (at most 4,096 px per axis, `ThumbnailGeometry.swift:7-20`) or answers with an error, then starts a `Task` (`Extensions/PrevThumbnailExtension/ThumbnailProvider.swift:19-33`).
2. `ContentThumbnailService.outcome` wraps the work in `ThumbnailRace` with a 1 s limit (`ContentThumbnailService.swift:64-70`, `ThumbnailLimits.swift:24`).
3. `produce` loads the App Group snapshot on every request (`:73`), applies the switch (`ThumbnailPolicy.swift:34-38`), builds a pipeline for this request (`ContentThumbnailService.swift:77-79`), classifies by metadata and the user's type choice (`PreviewPipeline.swift:17-20`), and requires policy `content` with a text presentation (`ThumbnailPolicy.swift:40-51`). Disabled, unsupported and `generic` types stop here with no read.
4. The pipeline runs with an explicit budget: 256 KiB of input, 512 KiB of output, 100,000 JSON nodes, 300 ms for every format except SQLite, which gets 4 MiB and 500 ms (`ThumbnailLimits.swift:36-45`). The reader stats before reading, refuses links and non-local iCloud items, and reads a leading prefix for line-oriented formats (`BoundedFileReader.swift:18-87`); the adapter parses, `DefaultPrivacyFilter` conceals, line metrics are validated, and the hidden-content scan runs (`PreviewPipeline.swift:47-124`).
5. `scene(for:)` withholds the whole document if anything was concealed (`ContentThumbnailService.swift:101`), then tries up to three document pictures in the order cover, icon, page, figure, decoded by ImageIO from an allow-list at no more than the canvas's pixel extent (`:104-110`, `ThumbnailImageDecoder.swift:13-41`), and otherwise builds a text shape: SQLite grid, notebook page, CSV/TSV grid, tab-separated plain text, JSON outline for long-line JSON, Markdown-like page, or excerpt (`ThumbnailContentBuilder.swift:12-37`).
6. The reply is `QLThumbnailReply(contextSize:)` whose drawing block paints the scene or, for every fallback reason, the glyph (`ThumbnailProvider.swift:35-47`). Cancellation is checked after the snapshot (`ContentThumbnailService.swift:74`), after classification (`:86`), before each decode (`:105`) and at the pipeline's checkpoints; Quick Look gives the provider no cancellation callback (decision 022:50).

### What a page holds at Finder's sizes

`ThumbnailMetrics` sizes the font from the page's pixel width, clamped to 7–15 px (`ThumbnailGeometry.swift:52-53, 70-77`):

| Request | Page (pt) | Font (px) | Cells (columns × rows) |
|---|---|---|---|
| 64 pt @1x | 48.6 × 60.8 | 7 | 9 × 6 |
| 64 pt @2x | 48.6 × 60.8 | 7 | 19 × 12 |
| 128 pt @2x | 97.3 × 121.6 | 10.1 | 27 × 17 |
| 256 pt @2x | 194.6 × 243.2 | 15 | 36 × 23 |
| 512 pt @2x | 389.1 × 486.4 | 15 | 73 × 46 |
| 1,024 pt @2x | 778.2 × 972.8 | 15 | 147 × 93 |

At Finder's default 64 pt the page is a texture (glyphs about 4 px tall), at 128 pt @2x text is just readable, at 256 pt @2x it reads; above that the font stays at 15 px and more text appears. The face is the user's fixed-pitch font (`ThumbnailRenderer.swift:99-100`), headings bold at 1.25×. The sheet is #F5F5F5 with a #525252 outline; ink is 16:1, the six syntax tones 6.4–7.8:1, comments 5.0–5.6:1 and muted #7A7A7A 3.9:1 against the sheet (computed). Thumbnails are deliberately not appearance-adaptive (`ThumbnailRenderer.swift:6-9`, decision 022:54), which matches macOS's convention of light document pages in dark mode; the sheet keeps 13–15:1 against dark window backgrounds and the transparent margins let Finder's selection plate show. The generic glyph is the same light page at 64% × 80% of the shorter side with three bars (`ThumbnailRenderer.swift:14-27`). The only appearance setting read is whether the user's syntax style uses colour (`ContentThumbnailService.swift:103`); without it every tone becomes ink. Fonts are sized in device pixels, strokes in points (TH-11). Nothing animates: an animated cover contributes its first frame. A disabled type, the switch turned off, an unreadable snapshot, a withheld document and a timeout all produce the same glyph.

### Privacy: what can reach a page

- Only two inputs are drawn: `TextPresentation.text` after the privacy stage, and document pictures an adapter validated (decision 022:26). The privacy stage conceals values under sensitive key names (`PreviewModels.swift:383-391`), ranges the adapters declare, and recognizable credentials anywhere in the text (private-key blocks, AWS and GitHub tokens, `sk-` keys, JSON web tokens, Bearer and Basic headers, `DefaultPrivacyFilter.swift:46-58`); any concealment withholds the whole document. Nothing guarantees recall for other secret shapes, and nothing conceals personal data.
- Strings that are drawn but are not values: JSON, YAML and TOML keys; CSV, TSV and SQLite column names; Markdown headings in full; notebook code; diagram source. Never drawn: file names, paths, archive member names (archives are `generic`), SQLite table names, notebook text outputs. A key, header or heading holds a secret only if a document puts one there, and the value patterns still catch recognizable tokens in it.
- The "sensitive formats stay generic" list covers environment files, certificates (including PEM private keys), provisioning profiles and HAR, plus INI and geodata. Several secret stores are not catalog formats (`.netrc`, `.htpasswd`, `.p12`, `.pfx`, `.ppk`, `.kdbx`, `.tfstate`, SSH keys and shell history without a suffix), so SpacePane never draws them and macOS decides; `.key` resolves to Keynote. Dot-named files such as `.envrc`, `.zshrc` and `.npmrc` are classified by name inside the pipeline, but macOS types such names as `public.data` (`finder-matrix-2026-10-04.md:40`), which only the preview registers. The real gap is inside `content` formats: `.tf` and `.tfvars` share the source-code policy (`FormatCatalog.json:397`), and logs and `.sql` files often hold credentials or personal data; each relies on recognized key names and the withholding rule, made durable by the cache (decision 022:58, TH-09).

### Time, memory and concurrency

- The budgets are 256 KiB of input, 300 ms of cooperative pipeline time and a 1 s race for every format but SQLite (4 MiB, 500 ms). Nothing depends on the requested size: metrics are computed after the pipeline (`ContentThumbnailService.swift:102`), so a 64 pt page costs the same reading, decoding and concealment as a 1,024 pt one, and a 1 MiB log is read up to its 256 KiB prefix to draw 12 lines of 19 cells.
- Shared state is one immutable service (`ThumbnailProvider.swift:14-17`) whose preference loader rereads the App Group document on every request; there are no caches between requests, and each request has its own pipeline and race.
- Memory per text request, estimated from the code and never measured (`thumbnails-2026-10-05.md:54, 66`): the file bytes, the decoded string, a UTF-16 copy for the regular-expression passes, a scalar array for the hidden-content scan when the text is not ASCII (about 1 MiB at the cap) and the concealed copy, a few MiB in all. SQLite adds a 4 MiB snapshot and 2 MiB of output; a picture adds up to 8 MiB encoded plus a bitmap at the canvas extent (4 MiB at 512 pt @2x, 64 MiB at the 4,096 px limit). A burst multiplies this by the number of requests running at once, which nothing limits (TH-07).

### Measured and observed

Release medians of 29–61 ms for 250 KB text inputs and 45–53 ms for a 1 MB SQLite file, excluding Quick Look's overhead, the drawing, cold start and memory (`docs/validation/thumbnails-2026-10-05.md:40-54`). In a host, the modern generator was attributed to this extension once, before decision 022, and produced the generic page for JSON at 256 × 256 (`parallel-expansion-2026-10-04.md:103-116`). No content thumbnail and no Finder surface has been observed (`thumbnails-2026-10-05.md:3, 60-69`; `parity-program-2026-10-05.md:68`).

### Strengths to keep

- Policy before parsing: the switch, classification, the user's type choice and the catalog policy all run before any adapter exists (`ContentThumbnailService.swift:73-86`), proven with counting factories and a counting reader for disabled, `generic` and switched-off requests (`ContentThumbnailServiceTests.swift:109-179`).
- Concealed-only input with whole-document withholding (`ContentThumbnailService.swift:101`, `ThumbnailLimits.swift:27`), tested at the default and with the limit lifted (`ContentThumbnailServiceTests.swift:192-228`).
- One audit point for everything drawn (`ThumbnailContent.swift:69-75`) and a test that neither the file name nor its folder is drawn (`ContentThumbnailServiceTests.swift:86-88`).
- Bounds everywhere: geometry, stat-before-read, an image allow-list with declared and real pixel caps, early-stopping line and JSON scanners, and an exactly-once race with 200-way interleaving tests (`ThumbnailRuntimeTests.swift:28-105`).
- A font-free cell model tested without a context, and a renderer tested on `CGBitmapContext` at 16–512 pt, 1x and 2x, off the main thread (`ThumbnailRendererTests.swift:152-196`).
- Clean composition: the extension injects `StandardFormatAdapters.registrations` (`ThumbnailProvider.swift:14-17`), the library has no AppKit (`Packages/PreviewCore/Package.swift:36`), and the product set is pinned so CAD code never reaches thumbnails (`script/validate_project.py:46-50`).
- `none` for STL, OBJ and PLY keeps Apple's 3D thumbnails (decision 024:59), and the website's privacy text already admits that the filter "can miss an unusual" secret (`web/public/locales/en/privacy.json:15`).

**TH-01. Eight "content" formats draw an app-made summary.** A Parquet, Avro, Arrow, NumPy or NPZ file always shows a page that begins `{`, `"dataFormat": "Parquet",`, `"formatVersion": 2,`, `"createdBy": …`, and an `.app`, IPA or CBZ shows the same kind of page whenever its icon or first page does not survive (TH-08). These adapters write a pretty-printed envelope with English camelCase keys and `syntax: .json` (`ParquetAdapter.swift:62-66`, `BundleInfoSummary.swift:14-22`, `ComicBookAdapter.swift:105-119`, `ContainerSupport.swift:101`), and the builder special-cases only SQLite and notebooks (`ThumbnailContentBuilder.swift:12-17`), so they fall through to the JSON excerpt (`:26-37`). This is app-authored text drawn into a graphic and never localized, which the multilingual rule names explicitly; it is Major rather than a Blocker only because the keys are schema identifiers. It also contradicts decision 022's "never falls back to drawing the raw summary JSON" (022:36) and "no app-authored text" (022:44), and decision 018 kept geodata generic for exactly this reason ("a text excerpt of a summary is not meaningful", `018-columnar-scientific-and-geo-data.md:30-32`). The data and ebooks workstreams asked this workstream to read `table`, `rowSample` and the pictures instead (`data-2026-10-05.md:87-89`, `ebooks-2026-10-05.md:63-64`); nothing consumed the request. Fix: never draw a summary as text; draw the tabular shape from the envelope (R3) or the picture only (R2), otherwise decline.

**TH-02. The generic glyph replaces informative system icons.** Whenever Quick Look selects this extension for a `generic` type, the reply is the same page with three bars for a ZIP, a disk image, an installer package, a certificate, a MIDI file, a STEP model or a folder (`Thumbnail-Info.plist:1478` registers `public.folder`). The system's own thumbnails for these types are type icons, and macOS's generic document icon for other types usually shows the extension (to be confirmed in the Mac table). Decision 024 moved STL, OBJ and PLY to `none` for exactly this reason (024:59) but the argument was not applied to the other 31 types. With `QLThumbnailMinimumDimension` at 64, list and column views would keep the system icon while icon view at 64 pt and up shows the glyph, so one file has two looks. `generic` has privacy value only where the system or another provider would otherwise draw raw text (environment files, PEM certificates, HAR, perhaps INI); for archives, packages and media it removes information and protects nothing. Whether Finder asks third-party providers for folders and `.app` bundles at all is unobserved (decision 017 doubts it for `.app`). Fix: decide per type from a Mac table of what the system draws when SpacePane does not register (R4), and give every type that stays a badge (R1) and a group symbol.

**TH-03. No type identity.** Apple's `QLThumbnailReply.extensionBadge` (macOS 12 and later) is "a short string that identifies the file type that the system uses as a badge when producing an icon thumbnail". Both replies are built without it (`ThumbnailProvider.swift:35-47`) and the drawn page has no type mark, so a folder of JSON, YAML, TOML and plist files at 64 pt is a grid of identical textures, and every withheld, disabled, oversized or generic file is the same glyph. The badge is the workstream's own deliverable (decision 026:83) and the cluster reports' main thumbnail recommendation (code-markdown recommendation 10). Fix: set `extensionBadge` on every reply from the catalog suffix the request matched (R1); draw a badge only where a Mac shows the system does not.

**TH-04. Source code may never reach the provider.** The source-code entry registers `public.source-code`, the app's imported type and optional QuickLook Pro aliases (`FormatCatalog.json:128-131`); the imported type tags only suffixes without a system declaration. Swift, C, C++, Objective-C, Python, JavaScript, shell, Ruby, Perl, PHP and Java resolve to concrete system identifiers (`.swift` resolved to `public.swift-source`, `finder-matrix-2026-10-04.md:35`) that are not listed. Apple's thumbnail article says the framework "only uses your extension for a file type if the listed UTI matches the file type. It's not sufficient to list a parent UTI", and the repository's own research recorded the rule (`docs/initial/01-macos-apis.md:41`). If it holds, the most visible competitor win, a Finder window of code thumbnails, never happens for the main languages. Fix: list the concrete identifiers each catalog suffix resolves to on macOS 15 and 26 (R5); the catalog is the lead's, and previews change too.

**TH-05. Real values and output figures in a durable cache.** CSV and TSV thumbnails draw the header and first rows (`ThumbnailTableBuilder.swift:13-31`), SQLite the first loaded page's values (`ThumbnailStructuredShapes.swift:11-20`), and the tests assert that `Ada` and `Bob` are drawn (`ContentThumbnailServiceTests.swift:68-69, 99-101`). Notebooks prefer any saved PNG or JPEG output to the cells, because pictures are tried first (`ContentThumbnailService.swift:104-110`) and the adapter returns outputs as `figure` images (`JupyterNotebookAdapter.swift:43-45`), although decision 022 describes notebook thumbnails as cells (022:32). Concealment hides credentials, not personal data, so a customer export's names and e-mail addresses go into the durable cache by default. Decision 026 rejects "real cell values in thumbnails" (026:113) and the synthesis cites decision 022 as the rule behind it (`competitor-ux-ui-analysis.md:101`), but decision 022 allows them; AGENTS asks to keep sensitive content out of thumbnails and durable caches. Fix: the shape-with-counts grid (R3), figures only if the owner wants them, and an amendment to decision 022.

**TH-06. Transient failures stick.** Every fallback reason, including `timedOut`, `cancelled`, `unavailable` (which covers iCloud items that are not local, `BoundedFileReader.swift:27-31`, and a locked SQLite file) and `settingsUnavailable`, becomes the same successful glyph reply (`ThumbnailProvider.swift:42-46`). Quick Look keeps successful thumbnails, and this product may not reset caches, so a request that missed the 300 ms deadline while Finder opened a large folder can leave a glyph until the file changes; glyphs drawn while the switch was off also stay after it is turned on. Fix: answer transient reasons with an error once a Mac shows how Quick Look treats errors (R6); PLAN already asks for that check without assuming an error hands the type to another provider (`PLAN.md:399`).

**TH-07. The hard timeout is not independent of the pool.** The race's timer is a Swift task (`ThumbnailRace.swift:113-116`) and the reply is sent from a Swift task (`ThumbnailProvider.swift:29-32`), so both need a cooperative-pool thread, and the pipeline's synchronous reads and parsing run on those same threads. The service builds one pipeline per request (`ContentThumbnailService.swift:77-79`), deliberately bypassing the serial worker that "bounds simultaneous blocking work" (`PreviewPipeline.swift:30-32`). A burst on a slow or network volume can therefore block every pool thread; then neither the timers nor the replies run, and the bound in decision 022:48 fails. The test suite already showed the effect: timers lost to CPU-bound work in the parallel run and had to be moved to a serial pass (`parity-program-2026-10-05.md:45`). Whether Quick Look sends requests concurrently is unobserved. Fix: answer from a Dispatch timer through a once-only gate and admit only a few pipelines at a time (R6).

**TH-08. Picture formats are starved.** Every format but SQLite gets 256 KiB of cumulative reads and 300 ms (`ThumbnailLimits.swift:36-45`), and this explicit budget wins over the 16 MiB container budget (`parity-program-2026-10-05.md:30`). EPUB covers are accepted only up to three fifths of it, about 154 KiB (`EPUBAdapter.swift:95`); the app adapter skips an `.icns` that does not fit what remains (`ApplicationBundleAdapter.swift:76-87`); the comic adapter reads page after page until the allowance is spent (`ComicBookAdapter.swift:29-43`), so a first page over about 200 KiB is lost. Each then falls back to TH-01's summary page. AVIF covers and pages, which the adapters accept (`EmbeddedImageValidator.swift:8, 13`), are refused by the thumbnail decoder (`ThumbnailImageDecoder.swift:13-15`). Real-adapter pictures were never exercised in the thumbnail path (`thumbnails-2026-10-05.md:69`). Fix: a picture budget, a first-picture-only option and AVIF (R7).

**TH-09. iCloud.** Apple's article says a thumbnail extension "also enables iCloud to generate a thumbnail alongside your custom file, enabling other devices to display the thumbnail once the file has been synced". If macOS does that for these types, a concealed excerpt of a document in iCloud Drive leaves the Mac as an image, beyond any later change of the switch. The repository's research noted it (`docs/initial/01-macos-apis.md:130, 176`), but decision 022's cache section (022:58), the switch copy and the website's privacy text speak only of the local cache. `SyncFolderLocation` already recognizes iCloud Drive and CloudStorage paths, though not Desktop and Documents sync (`SyncFolderLocation.swift:8-12`). Fix: verify on a Mac; the owner decides whether synced files get text, a shape or the glyph (R15), and the copy follows.

## Score against best-in-class

**2 of 5.** The safety architecture alone would score 4: nothing reaches a page without passing policy, concealment and the withholding rule, and the bounds are tested. The experience scores lower: no thumbnail has been seen in Finder, none carries a type, a fifth of the content formats draw a summary, 31 types trade a system icon for a type-less glyph, and the most common code types may never reach the provider.

A 5 looks like this in a Quick Look app: in Finder icon view at 64 pt and up, every registered type shows either a recognizable concealed miniature (code with syntax tones, a Markdown page with its heading, a table skeleton with counts, a cover or icon) or the system's own icon, never a type-less placeholder; each thumbnail carries the system type badge; text is legible at 128 pt and reads like a page at 512 pt; files that hold secrets show a badged generic page; a warm thumbnail appears within about 100 ms, a burst never stalls Finder and a busy moment never leaves a permanent placeholder; the behaviour is recorded per type on macOS 15 and 26 in icon view, Gallery, the preview pane and the Open panel with provider attribution; and tests pin shape, privacy (synthetic secrets and personal data), badge and pixels for every format.

## Open questions for the owner

1. **Cell values.** Decision 026 rejects real cell values in thumbnails; decision 022 draws the first CSV, TSV and SQLite rows. Should tables and databases become shape-only (R3) and decision 022 be amended? If not, the rejected list must change.
2. **Declined thumbnails.** When SpacePane declines (switch off, type off, `generic` policy, transient failure), should Finder show SpacePane's badged glyph or the system's icon through an error reply? This decides R4 and R6.
3. **Synced files.** If iCloud generates and syncs these thumbnails (TH-09), should files in iCloud Drive and other sync folders get text, a shape, or the glyph?
4. **3D thumbnails (pending).** Evidence, without a recommendation. Performance: one Release CAD import took about 1.11 s cold and 0.52–0.65 s warm with a peak of about 132 MiB (`cad-previews-2026-10-04.md:20`), against today's 300 ms pipeline and 1 s hard limit; the import service runs at most two imports per process (`cad-previews-2026-10-04.md:32`) and is embedded in the preview extension with an accepted-client requirement that AGENTS says to keep, so the thumbnail extension would need its own service, and the product set check forbids CAD code in it (`validate_project.py:46-50`); output may reach 500,000 triangles (`cad-previews-2026-10-04.md:9`), to be rasterized without the companion's Metal view. A folder of N STEP files at 64 pt costs N imports. A cheaper variant is 3MF's embedded package picture, which decision 024 left to this workstream (024:74): one archive member, no geometry, but the same shape disclosure, so it belongs in the same decision. STL, OBJ and PLY keep Apple's renders either way.
5. **Default.** Keep content thumbnails on by default once tables become shapes? The review's view is yes: the platform draws document content in thumbnails, SpacePane withholds any file in which it concealed something, and the remaining risk is pattern recall, which the website already states.
