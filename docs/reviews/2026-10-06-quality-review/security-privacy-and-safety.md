# Security, privacy and safety review — 2026-10-06

Reviewed from source only, on Linux, on 2026-10-06. Nothing was compiled, run, rendered or measured; every statement about runtime behaviour is inferred from the Swift, C, C++ and Python sources and from the repository's own validation records, and is labelled as such. This dimension covers the threat model for previewing untrusted files inside Quick Look: concealment of likely secrets and its reach across every output surface, hidden and bidirectional Unicode, bounded parsing and decompression in every container and binary reader, cancellation and deadlines, read-only guarantees, the sandbox and entitlements of the four signed bundles and the CAD helper, what reaches logs, the clipboard, accessibility and the Finder thumbnail cache, the adversarial corpus, and the supply chain. Verdict: containment, bounds and read-only discipline are excellent and well ahead of the category, but concealment has one wiring defect and several common misses that can flow into Finder's durable thumbnail cache, and liveness under blocking or online-only files was never designed for.

## Current state

The code base has a coherent, defensive design. The strengths below should be preserved as the fixes land.

1. **One gate before any read, one filter before any view.** Classification is metadata only and a disabled type returns before any registration runs or any byte is read (`PreviewPipeline.swift:51-53`). Privacy filtering, size and line validation and the hidden-content scan run after every adapter and before a presentation exists (`PreviewPipeline.swift:103-120`). Every derived mode is rebuilt from the concealed `presentation.text` (`SafePreviewModes.swift:149-235`), and copy actions read the same text (`NativePreviewView+Interaction.swift:126-139`, `NativeTablePreviewView.swift:471-484`).
2. **Read-only, no-follow access everywhere.** Files open with `O_RDONLY | O_CLOEXEC | O_NONBLOCK | O_NOFOLLOW`, the descriptor is checked to be a regular file, size is checked before reading, and size, mtime and ctime are rechecked after (`BoundedFileReader.swift:33-88`, `BoundedRandomAccessFile.swift:42-104`). Bundle walks resolve each component with `openat` and `O_NOFOLLOW` (`BundleDirectory.swift:93-111`); folder summaries are descriptor-relative, skip mount points and never open a file (`FolderScan.swift:5-21`); live reload watches with `O_EVTONLY` on regular files and folders only (`PreviewSourceMonitor.swift:122-137`); snapshots and themes are read the same way (`BoundedPreferencesData.swift:8-36`).
3. **Decompression is capped before allocation.** Inflate, bzip2 and xz produce at most 32 KiB per step against a hard cap, checkpoint between steps and refuse non-progress (`BoundedDecompression.swift:17-99`, `BZip2Decompression.swift:10-48`). xz dictionaries are preflighted and large ones go to an in-package bounded LZMA2 decoder (`BoundedDecompression.swift:61-165`). ZIP rejects overlapping members (the "better zip bomb"), checks local against central headers and bounds directory and metadata (`ZIPArchiveReader.swift:95-212`). 7z decodes only header streams, sizes checked first (`SevenZipListingAdapter.swift:113-149`, `LZMADecoder.swift:19-35`); TAR, PAX and cpio metadata are capped (`TARListingAdapter.swift:59-62`, `XIPListingAdapter.swift:116`). A test proves concatenated GZIP members cannot reset the cap.
4. **Graph and entity attacks are closed.** Binary plists are preflighted for count, depth, visits and cycles before Foundation sees them, and package plists reuse that path (`PropertyListSourceAdapter.swift:150-226`, `PackageSummarySupport.swift:165-176`). XML refuses every `<!` construct except comments and CDATA and disables external entities (`XMLSourceAdapter.swift:13-14,87`), as does draw.io (`DrawioDocumentReader.swift:66-79`).
5. **SQLite never sees the source path.** Bounded bytes are deserialized read-only into `:memory:` with DEFENSIVE on, trusted schema and extension loading off, an authorizer that admits only SELECT, READ, FUNCTION and four introspection pragmas, `SQLITE_PREPARE_NO_VTAB`, and a progress handler with a 250 ms per-statement deadline (`SQLiteInspectionAdapter.swift:13-58,271`, `PreviewSQLiteSafety.c:3-13`). Journal and WAL states are declined and read locks follow SQLite's own lock bytes (`BoundedFileReader.swift:51-61,93-103`); Finder showed it working (`docs/validation/finder-matrix-2026-10-04.md:49`).
6. **OCCT is contained.** The kernel runs in a posix-spawned helper with closed descriptors, a two-variable environment, bytes on stdin only, core dumps off, a 15 s CPU limit, a sampled 512 MiB footprint guard, discarded stdout and stderr, and kill-and-reap on every path (`CADWorkerProcess.swift:15-115`, `Native/CADWorker/main.cpp:18-84`). STEP external references are refused (`CADInput.cpp:99-100`), only a fixed numeric wire format returns and is validated before allocation (`CADMeshDecoder.swift:7-45`), and the XPC service accepts only the team-signed preview extension and fails closed without a team (`Native/CADImportService/main.swift:8-37`).
7. **Minimal entitlements.** Extensions hold the sandbox and the App Group, the CAD service only the sandbox, the helper sandbox and inherit; the app adds only user-selected read-write for theme export. No bundle has network access and hardened runtime is on (`Configuration/*.entitlements`, `Base.xcconfig:23-24`). The release check refuses temporary exceptions and network keys in every nested bundle (`check_release_archive.py:82-100`), and Spotlight indexing is off (`QLSupportsSearchableItems` false in `Preview-Info.plist`).
8. **Thumbnails are conservative.** Policy runs before any adapter; a document with any concealed value is withheld whole; images are type-allowlisted and size-capped; nothing app-authored and no file name is drawn (`ContentThumbnailService.swift:64-114`, `ThumbnailLimits.swift:24-27`, `ThumbnailProvider.swift:8-11`).
9. **Findings carry no values**; the one decoded Unicode Tag message passes the privacy filter first (`HiddenContentScanner.swift:119-148`), and invisible characters inside key names cannot defeat key matching (`PreviewModels.swift:372-397`).
10. **Logs are almost silent.** Only the CAD path logs, and only numeric status or errno (`CADImportService.swift:67,81`, `CADXPCClient.swift:32,36`, `CADWorkerProcess.swift:110,121`).
11. **Specialised privacy models are thoughtful.** HAR drops headers, cookies, bodies and query values (`HARAdapter.swift:6-11,162-199`); certificates count private-key blocks without decoding them (`CertificateAdapter.swift:9-11,45-48`); torrents reduce trackers to origins (`TorrentAdapter.swift:9-11,178-190`); SQLite conceals cells by table and column name and schema SQL that names a secret (`SQLiteInspectionAdapter.swift:74-77,112,262-266`); notebooks classify every decoded string token, escapes included (`NotebookPrivacyRanges.swift:91-131`); Markdown links and images stay inert text (`MarkdownInline.swift:4-5,165-166`). No document font is ever loaded and no PDF or web content is rendered.
12. **Companion inputs are strict.** Themes are a 16 KiB exact-key schema with no URLs or fonts (`AppearanceThemeCodec.swift:32-60`); bundled samples are path-validated (`AppearanceSampleLibrary.swift:33-55`); drops accept exactly one local file URL (`DirectPreviewFileDrop.swift:13-25`); the provider scanner reads only bounded `Info.plist` files under fixed roots and never through links (`QuickLookProviderScanner.swift:35-41,128-180`).
13. **Supply chain is pinned.** OCCT 7.9.3 is pinned by commit and SHA-256, built statically with a minimal toolkit set, and its archive members are checked for traversal and links (`build_cad_worker.py:13-16,80-94`, `docs/dependencies/occt.md`). The C shims expose decode-only and configure-only entry points (`BZip2Shim/include/PreviewBZip2.h`, `SQLiteSafetyShim/include/PreviewSQLiteSafety.h`).
14. **Concurrency hygiene.** Swift 6 complete checking with an explicit nonisolated default; only three `@unchecked Sendable` types, each with a written invariant (`PreviewSourceMonitor.swift:95-98`, `ImagePageDecoder.swift:5-9`, `ThumbnailProvider.swift:51-56`).

**Self-audit and decision 026 in this dimension.** The self-audit's line that "safety, privacy and honesty engineering is ahead of the visual communication" is right for containment and bounds and incomplete for concealment recall (SP-01, SP-03). Its privacy-touching proposals are correct: one privacy row that keeps the copy sentence (P3), tooltips only from concealed nodes (P10), copy of concealed cells only (P14). Decision 026's facts strip ("never a source value") and privacy row are compatible with this review; its code-block copy buttons and truncated-value tooltips must read from the concealed model and inherit R2 and R12. Two accepted statements need correcting. Decision 022's "one-second hard timeout ... answers with the glyph even if a native read or decode blocks" holds only while a cooperative thread is free (SP-05). The `PreviewImage` contract's "images never pass through text concealment" has silently extended to `label`, which is text (SP-02).

**SP-01, URL credentials (Blocker).** `EmbeddedSecretRanges.urlCredentials` conceals the `user:password` part of `scheme://user:password@host`, and its own comment calls these secrets "the shared assignment heuristic cannot see" (`EmbeddedSecretRanges.swift:3-10`), yet only three adapters call it: source code, logs and INI files. Every other text family reaches `DefaultPrivacyFilter`, whose value patterns do not include it (`DefaultPrivacyFilter.swift:46-58`) and whose key heuristic does not treat `DATABASE_URL`, `REDIS_URL`, `dsn` or `url` as sensitive. Emulating the filter on `.env`, YAML and plain text left `postgres://app:<password>@db/prod` unchanged. The user therefore sees database and broker passwords in `.env`, `docker-compose.yml`, `config.json`, JSONC, TOML, Markdown, notebooks, CSV, XML and extension-free files. For YAML, TOML, JSON, Markdown, plain text, CSV and notebooks the content thumbnail is not withheld, because `redactionCount` is 0, so the password is drawn into Finder's durable cache (`ContentThumbnailService.swift:101`). This breaks `AGENTS.md:22` ("Redact likely secrets by default. Keep sensitive content out of thumbnails ... durable caches") for a class the app itself already recognizes, and `AGENTS.md:47` (one owner per shared classifier). Fix with R1: make URL credentials a shared value pattern in the privacy filter, delete the three per-adapter calls, and test every text family plus the thumbnail path.

**SP-02, image labels outside the pipeline (Blocker by the review rule, low likelihood).** A comic page's archive member path becomes `PreviewImage.label` after only the key-name check (`EmbeddedImageValidator.swift:68-71`) and is set verbatim as the page's tooltip (`NativeImagePagesView.swift:210`); AppKit likely also offers a view's tooltip to assistive technology as help text (inferred). The label never passes the filter's value patterns or the hidden-character scan, so a page named with a token (`ghp_…`, `sk-…`, a JWT) is shown in clear on hover while the same name in a ZIP listing of the same bytes is concealed, and a right-to-left override in the name spoofs the tooltip. Practical likelihood is low, but this is the only text surface found that bypasses the shared privacy policy, which `PLAN.md:341` requires before any renderer or accessibility output. Fix with R2: drop the tooltip (the localized "Page n of m" label already serves) or filter labels in the pipeline and drop any that change or carry hidden characters.

**SP-03, recognition gaps (Major).** `SecretFieldPolicy.isSensitive` is a substring test over 16 words (`PreviewModels.swift:383-391`). Emulated against common inputs it misses `DB_PASS` and `SMTP_PASS`, `passphrase`, Docker's `"auth"` and npm's `_auth`, `*_KEY` names (`STRIPE_KEY`, `ENCRYPTION_KEY`, `SIGNING_KEY`, `APP_KEY`), kubeconfig `client-key-data` and Kubernetes `tls.key`, `Cookie: session=…`, `dsn` and webhook URLs, while it conceals `max_tokens`, `tokenizer`, `PWD` and `password_min_length`. The value patterns miss Stripe `sk_live_` and `rk_live_` (underscore, while the pattern expects `sk-`), Slack `xox?-`, Google `AIza…`, GitLab `glpat-`, npm `npm_`, PGP and PuTTY private keys, and base64-encoded PEM (`LS0tLS1CRUdJTi…`, the form kubeconfig and Kubernetes Secrets use). Layouts that carry the secret's name as a value are not seen: Kubernetes and ECS `name`/`value` pairs, .NET `<add key="Password" value="…"/>`, Android `<string name="api_key">`, PHP `define('DB_PASSWORD', '…')`, and space-separated `.netrc` and `.pgpass` lines. Inside JSON, XML and property-list strings the generic `password=` check is switched off (`DefaultPrivacyFilter.swift:102`), so `?api_key=…` in a JSON URL or `--password=…` in a JSON command stays visible although the same text is concealed in plain text and notebooks. These are the files developers preview most, and each miss in a `content` format also reaches the thumbnail cache (SP-04). Fix with R3 and R14, measured by a recall corpus.

**SP-04, thumbnail amplification (Major).** Decision 022 accepts that a secret the filter misses "can appear in a thumbnail and persist in that cache". The withholding rule fires only when the preview heuristics concealed something (`ContentThumbnailService.swift:101`), so thumbnail recall equals preview recall, although a false positive in a thumbnail costs only a generic glyph. With SP-01 and SP-03, ordinary `docker-compose.yml`, `kubeconfig.yaml`, `config.json` and README files can be cached with credentials, and the product rightly never clears shared caches. Pictures (covers, pages, figures, icons) are drawn by design and remain a documented residual risk. Fix with R4: a thumbnail-only, deliberately over-inclusive "may hold a secret" check that withholds before drawing (owner question 1).

**SP-05, blocking work on the cooperative pool (Major).** `PreviewPipeline.preview` is `@concurrent` and hops to a default actor whose synchronous body performs `read`, `pread`, inflate, ImageIO, Security, SQLite and the CAD XPC wait (`PreviewPipeline.swift:22-33`); the CAD client polls with `Thread.sleep` for up to its 20 s deadline (`CADXPCClient.swift:40-51`). All of it runs on Swift's cooperative thread pool, which has one thread per core and assumes no blocking. The thumbnail service builds one pipeline per request with no cap (`ContentThumbnailService.swift:77-79`), and its "hard" timeout is a `Task.sleep` that also needs a pool thread to resume (`ThumbnailRace.swift:14-17`). When enough requests block in the kernel (a stalled SMB or NFS share, a file being fetched, a slow external disk), the timer cannot fire and only Quick Look's own timeout applies. The preview path has no host-level timeout, and each controller's single worker queues later requests behind a stuck one (`PreviewViewController.swift:12`). This is a liveness defect rather than a data risk, and it contradicts decision 022's "Bounds" paragraph. Fix with R5.

**SP-06, dataless files (Major, needs a Mac).** The readers refuse only items whose ubiquitous downloading status is not current (`BoundedFileReader.swift:28-32`, `BoundedRandomAccessFile.swift:37-39`); the bundle walker reads files and the folder summary enumerates directories without any such check, and enumerating a dataless directory may itself ask the provider for its listing. Whether every File Provider domain reports those keys, and whether opening or reading a dataless file triggers a fetch, is not established here. If either fails, a preview or a Finder thumbnail of an online-only file asks the provider to download it inside a non-cooperative call, which can take arbitrarily long (SP-05) and contradicts `AGENTS.md:21` ("Never promise previews for missing bytes"). Fix with R6: make the guarantee independent of the keys through the documented I/O policy that refuses materialization.

**SP-07, image decode memory (Major, needs a Mac).** Embedded pictures may declare up to 100 megapixels (`DocumentLimits.swift:15`, checked at `EmbeddedImageValidator.swift:53-56`), and the Pages view decodes two at a time with `CGImageSourceCreateThumbnailAtIndex` (`ImagePageDecoder.swift:16-31`, `ImagePageScheduler.swift:18`). For codecs without reduced-resolution decoding (PNG and GIF at least), ImageIO probably decodes at full size before scaling: about 400 MB per 100 MP picture, from a file of a few kilobytes when the picture is a flat colour. The 192 MiB resident limit (`NativeImagePagesView.swift:85`) bounds retained bitmaps, not transient decode memory. The likely result is termination of the preview extension for a crafted CBZ, EPUB, FictionBook or notebook, against the 100 MiB target (`PLAN.md:534`). Thumbnails cap at 16 MP and are less exposed. Fix with R7 and measure.

## Score against best-in-class

**3.5 out of 5.** Isolation, bounds and read-only discipline would score 5: sandboxed extensions with no network, SQLite only in memory behind an authorizer, OCCT in a resource-limited helper behind a signed XPC check, no-follow descriptors everywhere, decompression capped before allocation and nearly silent logs. Concealment, the product's own promise, scores lower: one recognizer reaches only three formats, common credential names and token formats are missed, recall is unmeasured, and each miss can persist in Finder's thumbnail cache; liveness under blocking volumes and memory under hostile images are unmeasured, and there is no surface-wide leak test or fuzzing.

A 5 for this dimension in a Quick Look app is observable: a canary corpus of the 40 most common credential formats, written into every catalog format, is run through every output surface (displayed text, every derived mode, every copy action, tooltips and accessibility values, find, the findings banner, thumbnails and logs) with zero escapes, and recall and false-positive rates are recorded in a validation record; thumbnails withhold anything secret-shaped; every parser has a fuzz harness with a recorded number of crash-free CPU hours under AddressSanitizer; previews and thumbnails stay responsive with a dead network share and online-only folders and never trigger a download; peak extension memory with hostile images and archives is measured under the plan target; and the release check enforces exact entitlements for every bundle.

## Notes for other dimensions

- **performance:** SP-05 is also a throughput issue. The SQLite registration has no default budget, so any database over 1 MiB fails as too large in previews (`Containers/ContainerFormatAdapters.swift:5`, `PreviewModels.swift:140`) while thumbnails allow 4 MiB (`ThumbnailLimits.swift:39-41`). XIP decoding can grow a `Data` to 64 MiB with doubling growth (`XIPListingAdapter.swift:29-74`), and the LZMA header decoder preallocates up to 8 MiB from a declared size (`LZMADecoder.swift:132`).
- **structured-views:** logs with ANSI colour escapes are refused as binary because `TextMetrics` rejects ESC (`PreviewCore/TextDecoder.swift:84-86`). The R3 sibling rule will add concealment tokens to Outline values of Kubernetes and ECS manifests.
- **thumbnails:** SP-04 and R4; SP-17 means AVIF covers are never drawn. Decision 026's "shape-with-counts" drawing must count only facts from the concealed model.
- **chrome-states:** if R12 lands, the privacy row and the Copied chip should say when hidden characters were removed. R2 removes a page tooltip. The facts strip must never use image labels.
- **documents-media-3d:** SP-07 and R7 (`Images/*`, `DocumentLimits`), SP-08 for EPUB, FictionBook and web-archive text, SP-14 and R15 for CAD in the companion.
- **architecture:** SP-12 asks for one recognizer owner in contracts; R5 changes the core worker's executor and must be recorded as a shared-core edit; `Package.swift` applies `unsafeFlags` to every target, which is fine locally but blocks reuse as a remote package.
- **platform-release:** R11. The CAD service requirement depends on `DEVELOPMENT_TEAM` being set in the archive configuration (`Native/CADImportService/main.swift:27-32`); confirm on macOS 15 that the team-prefixed App Group raises no container-access prompt.
