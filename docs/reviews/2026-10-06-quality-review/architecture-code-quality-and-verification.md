# Architecture, code quality and verification review — 2026-10-06

Reviewed from source only, on Linux, on 2026-10-06; nothing was compiled, run, rendered or measured, and every runtime statement below is inferred from code and from the repository's own validation records. This dimension covers module boundaries against the AGENTS.md modularity rules, the size and responsibilities of the largest types, where parsing lives, dependency direction, Swift 6 concurrency configuration, error typing, tests, build and validation tooling, documentation hygiene and, above all, how decision 026's seven workstreams can author Swift safely without a compiler and verify it later on a Mac. Verdict: the domain architecture (contracts, pipeline, catalog, privacy boundary, typed findings) is genuinely strong and well tested, but the renderer hub (`NativePreviewView` plus `SafePreviewModes`) and a verification chain that only runs on one Mac by hand are not ready for seven parallel workstreams writing blind; a short pre-work phase (test seams, a decomposition of the preview view, the lead's contract additions, a portable static gate and a macOS CI job) should come before any workstream branches.

### Concurrency (question 3)

`-default-isolation nonisolated` (`Packages/PreviewCore/Package.swift:8`) and `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated` (`Configuration/Base.xcconfig:17`) are SE-0466's switch. `nonisolated` is already the compiler's default, so both settings only state intent; they matter because Xcode 26 project templates choose main-actor isolation for new targets, and they keep SwiftPM and Xcode builds identical. With `SWIFT_APPROACHABLE_CONCURRENCY = NO` (`Configuration/Base.xcconfig:18`), nonisolated async functions already run on the global executor, so the explicit `@concurrent` annotations are future-proofing. PackageDescription 6.2 has a native `defaultIsolation` setting, but `-application-extension` still needs `unsafeFlags`, so replacing the flag gains nothing.

Inventory in package sources, with the app and extensions in parentheses: 64 `@MainActor` (16 more), 11 `Task {` (7 more), no production `Task.detached`, 2 `DispatchQueue`, 3 `@concurrent` (2 more), 5 `isolated deinit` (5 more), 7 `Mutex`, 1 `Atomic`, and the actors `PreviewWorker`, `PreferenceStore` and `AppearanceThemeReader` (plus `QuickLookProviderScanner` in the app). Main-actor isolation is declared on every AppKit type and every `@Observable` store; derivation types are nonisolated values that run wherever they are called, which today is the main actor (`Packages/PreviewCore/Sources/PreviewRenderers/NativePreviewView.swift:299`). File I/O is off the main actor everywhere except the monitor's `stat`, `open` and `fstat` when live reload starts (AR-14). New UX types carry three specific risks: plain helper classes that touch views are nonisolated by default in this module and must be annotated (`NSView` subclasses inherit `@MainActor`); the 300 ms spinner and 1.5 s Copied chip need a cancellable main-actor task per view, the pattern already in `Packages/PreviewCore/Sources/PreviewRenderers/NativeMIDIPlayback.swift:56-63` with an injected clock, never `Timer` closures (their blocks are `@Sendable`) and never a new wall-clock test; and `NSPopover`, `NSProgressIndicator`, `UndoManager` and `.searchable` have never been used in this repository, so their Swift 6 annotations are unverified here.

`PreviewFailure` has 17 cases without associated values (`Packages/PreviewCore/Sources/PreviewContracts/PreviewModels.swift:108-115`); `PreviewOutcome` has five (`Packages/PreviewCore/Sources/PreviewContracts/PreviewModels.swift:117-123`); thumbnails, live reload and preferences have their own typed results. **AR-01, no CI and no macOS 15 evidence.** Every Swift check depends on someone running `--check-compiler` and `--test` on one Apple silicon Mac with macOS 27.2. During a program authored without a compiler, a broken commit is invisible until that session, and every commit after it is built on an unknown base. The validation records repeatedly list macOS 15 runtime as unverified, although the package suite could run there unchanged: the code contains no availability checks at all (`rg '#available|@available'` finds none in sources), so it only uses macOS 15 APIs, and its hardware-dependent tests are opt-in. A macOS CI job would catch compile and test regressions on every push and, on a macOS 15 image, provide the first baseline-OS runtime evidence. Rule touched: AGENTS.md "Verification and completion" (distinguish package, compile and host evidence).

**AR-02, a Mac-only gate.** On Linux, `--check` passes its first step and fails at the second. Four of the seven already run here (manifests, samples, localization-tool tests, `bash -n`), and a fifth, `validate_localization.py`, shells out to `plutil` only to parse generated `.strings` files that `tools/generate_localization.py:39` writes as `json.dumps`-quoted pairs; the scratch parser matched all 924 keys in all 14 locales. Only the project-graph validation and the icon render need macOS. Separating a portable `--check-static` from the Mac-only project, plist and icon checks gives blind authors the same gate the Mac uses. Rule touched: AGENTS.md "check references and localization/resource availability during review and builds".

**AR-03, one view owns five workstreams.** `display` interleaves outcome dispatch, mode recomputation, MIDI state, notices, view visibility, reading-position restoration and styling in 145 lines whose locals depend on each other; it is the riskiest function in the repository to edit without a compiler and five workstreams need it. Decision 026 resolves conflicts by giving the file to ux-chrome, but the deliverables of ux-modes-structure (default-first order, per-format labels, Command-Option-n), ux-copy (title and body), ux-containers-3d (limits moved out of listing views), ux-documents (the offline notice only when something was blocked) and the lead (strip slots) all land in it. Either the program serializes on this file or it is decomposed first (R4). Rule touched: AGENTS.md single responsibility and the collaboration rule "assign disjoint file ownership".

**AR-04, structural tests.** The renderer suite finds the status label as "the first `NSTextField` among direct subviews" and the mode control as "the first `NSSegmentedControl`". The header row, facts strip and privacy row of contract 1 necessarily nest these controls, so about 75 assertions in 24 files will fail although behaviour is preserved, and those files belong to no workstream. Named, hierarchy-independent seams (the repository already has one, `dataProfileIsComputed`, `Packages/PreviewCore/Sources/PreviewRenderers/NativePreviewView.swift:222`) and one shared `descendants(of:)` should land first, as a test-only change that a Mac run confirms green before any production refactor. Rule touched: AGENTS.md "Keep native outline expansion/selection and reusable-cell accessibility metadata covered by the renderer regression tests".

**AR-05, facts in text.** Decision 026 asks for a facts strip "derived from fields the presentations already carry". Those fields are not reliable facts: `lineCount` counts lines of an app-made JSON summary for archives and databases, `byteCount` is zero for folders, `encoding` reads UTF-8 for random-access and URL inputs, and the counts the strip wants (entries, pages, records, cues, rows, partial, DRM) are either in summary JSON that the renderer must re-parse on the main thread or in a field with three meanings. A typed `PreviewFacts` value produced by adapters, carrying counts and flags but never source values (the same rule as findings), is the contract the strip needs. It is a `PreviewContracts` change, so under decision 026 only the lead can make it, before the workstreams start. Rules touched: AGENTS.md typed IDs and "parsers return typed results", decision 012's no-source-values rule.

**AR-06, ownership.** The ownership check ran decision 026's table against the renderer tree: 76 of 131 files are unowned. Most are AppKit-free derivations nobody needs, but some deliverables cannot be built inside the owned set: Command-Option-n needs `PreviewShortcut.swift`; the companion's Try Preview state view and any new `display` parameter need `NativePreviewPane.swift`; Undo needs `CompanionSettings.change` (`Apps/PrevApp/Stores/CompanionSettings.swift:121-136`); the Try Preview inspector needs `PreviewSession`; tests and the Python model-check list (`script/test_companion_models.py:14-29`, plus the hand-counted "Passed 11" at `Tests/Integration/CompanionModelChecks.swift:32`) are unowned. Separately, "each workstream adds strings only below its own marker in the string files" cannot apply to `.xcstrings` or the translation JSON, which have no comments and are written in insertion order. Rule touched: AGENTS.md collaboration ("assign disjoint file ownership and agree shared contracts before parallel edits").

**AR-07, blocking work on the cooperative pool.** `PreviewWorker` is an actor whose `preview` method reads files and runs parsers synchronously, so each in-flight request occupies one cooperative thread, and `ContentThumbnailService` deliberately creates one worker per thumbnail request. When Finder asks for many thumbnails at once, blocked workers can occupy the pool that `ThumbnailRace`'s timer task needs in order to resolve "the bound that still holds when a native read or decode blocks" (`Packages/PreviewCore/Sources/PreviewThumbnails/ThumbnailRace.swift:3-5`). The parity program saw exactly this in tests and moved five tests to a serial pass instead of changing the executor. Giving `PreviewWorker` a custom serial executor backed by a `DispatchSerialQueue` (SE-0392, macOS 14+) keeps blocking work off the pool without changing any API. This needs measurement on a Mac before it is called a defect. Rule touched: AGENTS.md "Each request owns cancellation, resource budgets... A deadline does not forcibly preempt noncooperative native code".

## Score against best-in-class

**3 / 5.** The code architecture alone would score 4: the pipeline, contracts, catalog, privacy boundary and typed findings follow the AGENTS.md rules closely, the test suite is large and deterministic where it matters, and concurrency is strict and documented. Verification infrastructure and the renderer hub pull the score down: no CI, a gate that only runs on one Mac, a 1,087-line view that five workstreams must edit, structural tests that will break under the planned chrome, and facts that the planned chrome cannot obtain honestly.

A 5 for this dimension in a Quick Look app looks like this: every pull request runs a macOS job that builds the package, runs the full suite on the deployment-baseline OS and type-checks both extensions in under 20 minutes; a portable static gate (manifests, catalog, strings and generated resources, Swift syntax, file ownership, decision numbering) runs anywhere in under a minute; no view type exceeds about 400 lines, and preview chrome, non-content states, content hosting and mode policy live in separate, separately tested files, so adding a mode touches one registry line plus its own files; adapters hand typed, value-free facts and limits to the chrome; timer behaviour is tested with injected clocks, never with wall time; test helpers live in one support target; and decisions, plan and validation records are indexed, uniquely numbered and provably in sync with generated artifacts.

### Rules for Swift written without a compiler

1. Use only APIs that already have a call site in this repository (find it with `rg` and copy its shape), or that Apple documents as available on macOS 15 with an unchanged signature; the code has no availability checks today, so never introduce one blind. A first use of a new API (`NSPopover`, `NSProgressIndicator`, `UndoManager`, `.searchable`, `DispatchSerialQueue`) goes in its own small commit behind a narrow wrapper and is flagged for the Mac session.
2. Mirror the repository's concurrency patterns exactly: `@MainActor final class X: NSView`, `@MainActor @Observable final class` for stores, nonisolated `Sendable` value types for models, `isolated deinit` for teardown, `@objc nonisolated` plus `Task { @MainActor [weak self] in … }` for notifications, `@concurrent` for blocking work, `Mutex` for shared state. Annotate every new reference type that touches AppKit, because the module's default isolation is `nonisolated`.
3. Keep blind edits inside one module. Cross-module access changes, implicit memberwise initializers used from another module, `Package.swift` target changes, resource moves and `Prev.xcodeproj` edits wait for a Mac.
4. After adding an enum case, list every `switch` over that enum with `rg` and update each; the compiler cannot remind you here.
5. Keep SwiftUI bodies small and extract subviews; type-checker timeouts cannot be detected blind.
6. Tests first, in their own commit, written against named seams and pure models with exact English expectations (`languagePreferences: ["en"]`) and explicit locales; on the Mac, run them against the old code to see them fail for the right reason, then against the change.
7. One concern per commit; run the static gate and the syntax gate before each push; mark the changelog entry "Verified: static checks only; not compiled" and list the commit in the program's validation record.
8. Never add a test that waits on wall time; inject the clock or scheduler.
