# Documents, media and 3D review — 2026-10-06

Reviewed from source only, on Linux, on 2026-10-06. Nothing was compiled, run, rendered or measured, so every statement about what a user sees is inferred from the Swift sources and from the repository's own validation records, and is labelled that way. The dimension covers how SpacePane presents reading documents (rendered Markdown, the LaTeX, AsciiDoc, reStructuredText, Org, Fountain and BibTeX renderers, the Contents mode, Jupyter notebooks, EPUB, FictionBook and web archives), pictures (comic and ebook Pages, notebook figures, package icons), native Mermaid and draw.io diagrams, coordinate plots, subtitle cues, the 3D geometry viewer for IGES, STEP and meshes, and the MIDI strip. Verdict: the pipeline under these views is safe, bounded and unusually thorough, but reading documents are typeset as code (monospaced, unmeasured, unreflowed, with tab-misaligned tables and colour-only code and quotes), ebooks print untranslated adapter labels, and the 3D view most likely shows a near-black, sideways, unit-assumed model to light-mode users of STL and 3MF files.

## Current state

The engineering under this dimension is strong and should be preserved:

- **Inert, native rendering from concealed text only.** Seven markup dialects, notebooks and three ebook formats share one decoration model and one bounded builder (`Markup/MarkupBuilder.swift:16-21`, 20,000 decorations, 262,144 UTF-16 units, failing closed to Source with a notice). Links never become link attributes and automatic link detection is off (`NativePreviewView.swift:97`, `Markup/MarkdownInline.swift:3-5,165-166`), so link text cannot hide its target; HTML stays literal; includes and image targets are shown, never followed.
- **Bidirectional text done properly.** Paragraphs whose first strong character is right-to-left get a right-to-left base direction and natural alignment, per UAX #9 rules P2 and P3, while code, math and rules stay left-to-right (`MarkupBuilder.swift:117-176`, `MarkupDirection.swift:3-45`, `NativeMarkdownStyling.swift:75-77`).
- **Honest approximations.** Unknown TeX stays visible (`MarkupMath.swift:3-8`), a notice says formulas are approximated (`MarkupRendering.swift:41-49`), citation styles carry a caveat, footnote numbers are Unicode superscripts that copy and read correctly (`MarkupFootnotes.swift:44-69`).
- **Contents** selects the exact heading range collected while rendering, activates from the keyboard, and gives each row a localized "Heading level n: title" label and hint (`Markup/MarkupContentsView.swift:107-132`).
- **Notebooks** are rendered defensively: escaped labels, fence-collision handling, terminal escape stripping, truncation at cell boundaries with a localized count (`SafeNotebookDocument.swift:93-123,332-421`).
- **Pages** decode lazily off the main actor, two at a time, nearest first, within 4,096 px and 8 MP per picture and 192 MiB resident, and a late decode can never revive a released page (`Images/NativeImagePagesView.swift:84-89,283-340`, `ImagePageScheduler.swift:3-80`, `ImagePagesLayout.swift:20-21,94-104`). Comics say "Showing the first 3 of 1,200 pages" with locale digits (`DocumentPresentationNotices.swift:19-24`).
- **Diagrams** are Core Graphics drawings in palette colours with High Contrast handling (`Diagrams/NativeDiagramView.swift:61-76`), anchor-stable zoom, refit until the user zooms (`:95,128-154`), and a bounded accessibility tree with one element per node and a connection summary (`:241-288`).
- **The plot** draws only parsed coordinates, says no tiles or network are used, and states simplification (`Data/NativePlotPreviewView.swift:4-8,39-52`).
- **3D** keeps a numeric-only importer boundary, creates Metal lazily, draws on demand with no idle loop, follows host-managed visibility and keeps the camera across suspension (`GeometryMetalRenderer.swift:6-7,34-35`, `NativePreviewView.swift:226-244`). Measurements are honest about open surfaces and use four significant digits (`NativeGeometryPreviewView.swift:121-157`); header facts pass a safe alphabet (`GeometryPresentation.swift:79-107`); the viewport is an accessible image with label, value and help (`NativeGeometryPreviewView.swift:270-274`).
- **MIDI** never autoplays, restores controller state without replaying notes on scrub, validates every event, and closes the audio graph on suspension (Finder's disappearance), window occlusion in the companion, window close and deinit (`NativeMIDIPlayback.swift:45-148`, `NativePreviewView.swift:224-230,425-435`).
- **Tests and records** are extensive and candid about what was not observed (for example `mesh-2026-10-05.md:9`, `diagrams-2026-10-05.md:52-67`).

**DM-01 (Blocker).** A user opening an EPUB, FB2 or MHTML file in Turkish or Japanese sees, at the top of the Rendered view, a tinted block of English labels written by the adapter (`title:`, `author:`, `language:`, `publisher:`, `date:`, `identifier:`, `description:`, or `source:` and `resources:` for web archives), followed by machine flags such as `partial: true` or `drm: true`; images with alt text appear as English `[image: …]` markers. Adapters write these because they cannot localize (`MarkdownWriter.swift:285-289`, `EPUBAdapter.swift:59-62`, `WebArchiveAdapter.swift:38-42`, `HTMLMarkdownConverter.swift:224`, `FictionBookAdapter.swift:199,264`), and `MarkdownRenderer.frontMatter()` prints every entry (`MarkdownRenderer.swift:114-143`). The flags also restate the localized status notice (`DocumentPresentationNotices.swift:14-17`), so one fact is said twice. This breaks the AGENTS rule that every app-authored user-visible string is localized. The fix belongs in the renderer for `DocumentPresentationNotices.documentFormats`: drop `key: true` flag lines, show known keys with localized labels or as a centred title block, and turn images into one localized marker (DM-R1).

**DM-02 (Major).** Rendered documents inherit every code setting: the code face (`NativeTextAppearance.swift:141-143`, applied at `NativePreviewView.swift:550-557`), the code line spacing (0 by default, `NativeTextAppearance.swift:73`), no paragraph spacing, a full-width container (`NativePreviewView.swift:676`) and the code wrap switch (`:576`). Meanwhile code spans and blocks use `NSFont.monospacedSystemFont` whatever family the user picked (`NativeMarkdownStyling.swift:27,34`) and headings use SF Pro bold (`:31`), so a chosen coding font shows in the prose and not in the code. The result is about 98 characters per line in an 800 pt window and 190 full screen, at a leading of roughly 1.2. Decision 026's principle 6 ("Match type to content and bound the measure") and doc 05's Code/Prose/Data typeface row (`docs/initial/05-ui-ux.md:134`) ask for a reading face, open leading and a bounded measure; the code-and-Markdown cluster names Peekdown and Anybox Markdown (New York body) as the bar. **DM-03 (Major).** `MarkdownRenderer` keeps one output line per source line (`MarkdownRenderer.swift:8-10`, `emitParagraph` at `:312-320`; decision 015 records "Lines are not reflowed"), while LaTeX, AsciiDoc, reStructuredText and Org reflow. **DM-04 (Major).** Every dialect writes a table row as its cells joined by a tab (`MarkdownRenderer.swift:583-586`, `MarkupBlockWriter.swift:127-136`, `LaTeXRenderer.swift:783`), and the paragraph style has no tab stops, only a default interval of four space advances, about 31 pt at 13 pt (`NativeTextAppearance.swift:77-80`). ## Score against best-in-class

**2.5 out of 5.** On substance this dimension is at or ahead of the field: seven inert markup dialects, notebooks, ebooks, native accessible diagrams, bounded page decoding, honest approximations and 3D facts (area, volume, bodies, schema) that no Quick Look competitor shows. On presentation it is behind the leaders the research names: reading text is laid out as code with misaligned tables and colour-only code and quotes, ebooks show untranslated adapter labels, notices are unconditional or repeated, and the 3D view is probably illegible in light mode and sideways for printing formats. Most fixes are local to files this workstream can own, and several need no Mac to author.

A 5 in a Quick Look app looks like this, observably. A README opens in a reading face at the user's size with about 1.4 leading in a centred column of about 70 characters, hard-wrapped paragraphs reflow, headings have a clear scale with space above, code sits on a tinted card with its language and a copy action, quotes and alerts carry a leading bar (trailing in right-to-left paragraphs), tables align in columns, images appear as a localized "Image: alt" marker, and everything stays distinguishable with colour off. A notice appears only when something was actually not loaded ("2 images are not loaded"), and only in the mode it describes; ebooks say "Showing chapters 1–12 of 38" in the reader's language with no adapter jargon. Wide windows show a Contents rail that follows the reader; narrow panes do not. Pages show "Page 3 of 1,200" and failed pages say so. Diagrams open legible and Command-Plus zooms them. A 3D model opens upright for its format in a mid-tone shaded material in every scheme including High Contrast, with a compact labelled control group, dimensions in the declared unit or "unit not declared", a body count, a hint that disappears after the first drag, a spinner after 300 ms during import and a designed failure state. MIDI is one labelled transport row in palette ink. None of it takes Space or the arrows from Quick Look, and VoiceOver reads images, headings, pages and model facts in all fourteen languages.
