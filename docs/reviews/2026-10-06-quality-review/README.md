# Ten-dimension quality review — 2026-10-06

Reviewed on 2026-10-06 from source only, in a Linux container with no Swift toolchain, no Xcode and no macOS. Nothing was compiled, run, rendered, measured, spoken by VoiceOver or observed in Finder. Every runtime statement in these reports is inferred from the Swift, C, C++ and Python sources, from Apple's documentation, or quoted from the repository's own validation records, and each report says which. The review follows [the competitor UX/UI analysis](../../market/2026-10-06-competitor-ux-ui-analysis.md) and [decision 026](../../decisions/026-world-class-ux-program.md), which compared presentation; this review covers quality and performance across ten dimensions so that the implementation plan in [decision 027](../../decisions/027-best-in-class-quality-program.md) rests on the whole product, not on presentation alone.

## Method

Ten reviewers worked in parallel against one brief (the same evidence rules, severity scale and report template), each owning one dimension and one report. Each read the sources in its scope in full, verified the self-audit's claims and decision 026's assumptions for its area, ran the three repository checks that work on Linux (`script/sync_manifests.py --check`, `script/generate_appearance_samples.py --check`, `tools/test_localization.py`; all pass) and, where useful, read-only analyses written outside the repository (catalog metrics, WCAG contrast arithmetic, a Python port of the YAML outline parser over a corpus, a dry run of the localization tools, a tree-sitter parse of all 601 Swift files). The lead cross-checked the reports against each other, resolved contradictions, and wrote the synthesis below and the plan.

Severity: **Blocker** violates a product rule (privacy, read-only, honesty, single window, localization) or breaks a core flow; **Major** materially degrades quality for many users or formats; **Minor** is a polish issue; **Cosmetic** is small. Confidence: verified in code, inferred, or needs a Mac.

## Findings that cut across dimensions

1. **Decision 026 cannot be implemented as written.** Seven reports found the same structural problems: 76 of 131 renderer files, the extension hosts, the companion's stores and models, and every test file have no owner; the "marker" rule cannot apply to the JSON string catalogs, which are insertion-ordered; `PresentationFacts` cannot be derived honestly from today's presentation fields (byte counts are zero for folders, line counts describe app-made JSON for containers) and must live in a UI-free module so thumbnails can share it; failure bodies with limit values need a contract that carries the effective budget; gate 2's loading spinner is probably never visible in Finder because the Quick Look completion handler is called after the whole display; gate 5 depends on a popover and tooltips in the remote view that nothing has verified; gate 4's muted tier cannot be both 4.5:1 and visibly lighter than body text in Solarized Light, Solarized Dark and One Dark; gate 11 names CSV, which the benchmark does not measure, and sets a tolerance below the recorded run-to-run noise; principle 2 is already broken by focus-scoped Space and arrow bindings in Contents, Pages, 3D and diagrams; the "no overlays" rule contradicts the decision's own floating 3D controls and code-block copy buttons; the rejection of real cell values in thumbnails amends decision 022 rather than restating it; and there is no thumbnail gate. Decision 027 amends 026 before any workstream branches.
2. **One scheduling defect, four symptoms.** Blocking reads, parsers, ImageIO, SQLite and the CAD wait loop run on Swift's cooperative thread pool. The thumbnail "hard" timeout, the reply to Quick Look and the serial wall-clock tests all depend on a free pool thread, which a burst of blocked reads removes (security SP-05, performance PF-06, architecture AR-07, thumbnails TH-07). The fix is one change in the pipeline worker's executor plus an admission limit and a Dispatch-driven timer, scheduled as a lead contract item.
3. **Completion-handler timing shapes both perceived speed and the loading state.** The extension calls Quick Look's handler only after preferences, the pipeline and the full synchronous display, so Finder shows its own spinner for the whole wait and SpacePane's loading state is never seen (performance PF-05, platform PI-04, chrome CH-11). The policy has to be chosen after a Mac observation and before `NativeStateView` is built.
4. **Honesty defects in shipped copy.** Six Blockers and several Majors are sentences, not architecture: the table notice that claims "Source shows the complete concealed text" for tables whose Source holds the same bounded rows (SV1, CH-1); the File Types subtitle that promises what Finder previews (CO-01); the website's instruction to look for a "Preview by" status line that no longer exists (PI-07) and an OS requirement that omits Apple silicon (PI-08); rendered ebooks that print English adapter labels and machine flags in every language (DM-01); citations with English-only terms (AL14); and thumbnails that draw app-made summary JSON with English keys (TH-01). All are fixable without a compiler.
5. **Concealment recall, made durable by thumbnails.** URL credentials are concealed only by three adapters, so `postgres://user:password@host` shows in `.env`, YAML, TOML, JSON, Markdown, plain text, CSV and notebooks, and content thumbnails of those files are cached by Finder with the password drawn (SP-01). Common names and token formats are missed (SP-03). Comic page labels bypass the filter (SP-02). The fixes are small and testable; a recall corpus makes the result measurable.
6. **Counts need plurals and the tooling refuses them.** Decision 026's facts strip, limits strip and privacy row ("1,204 lines", "3 likely secrets hidden", "{8 keys}") need plural forms in 14 languages; the generator and validator reject variations by design (CH-9, AL2, SV20). Either the tooling grows a `.stringsdict` path first, or chrome keeps label-colon notation. The plan builds the tooling.
7. **Keyboard access is weaker than the code suggests.** The mode control has no accessibility label and no shortcut, so without Full Keyboard Access most keyboard users cannot reach Outline, Table or Files at all (SV3, AL3, CH-14); every shortcut matches the typed character, so ⌘L, ⌘F and ⌘C in the preview likely do nothing on Russian, Hindi, Bengali and kana layouts (AL5, CH-16); and whether Quick Look delivers any key equivalent to the extension view is unverified.
8. **Performance is a main-thread problem.** Whole-document TextKit layout before the first frame and again after every restyle, eager outline and record models built with a scanner that runs `JSONDecoder` per string and a regex per scalar, per-token attribute application, full restyles on no-op events, and an O(text × ranges) concealment rebuild without a checkpoint (PF-01 to PF-04). The 200 ms warm target stays open for text, JSON, JSON Lines and source until these change, and the program's gate 11 cannot tell whether a chrome change made it worse.
9. **The verification chain is one Mac, by hand.** No Swift continuous integration; `--check` stops on Linux at a step that only needs `plutil`; 75 renderer assertions find views through direct subview order and will break under the planned chrome; the preview view (1,087 lines, 49 stored properties) is the integration point of five workstreams (AR-01 to AR-04). This matters most for a program authored without a compiler, which is the situation of every cloud session.
10. **Platform evidence lags the product.** Finder was never observed with the production bundle identity; 51 of 76 formats have no Finder observation; Gallery, Spotlight, full screen, cold start, update and language in Finder were never observed for any format; macOS 15 never ran the app; the CAD XPC peer requirement probably rejects the App Store re-signed extension; source-code thumbnails are registered under a parent type that Apple says thumbnails do not match; there is no privacy manifest; the OCCT licensing route is open (PI-01 to PI-11, TH-04). The program must therefore start with a Mac session, not end with one.
11. **Reading documents are set as code.** Monospaced prose with code leading, no measure, no reflow of hard-wrapped Markdown, tab-joined tables, colour-only code and quote cues, an unconditional offline notice on eleven formats (DM-02 to DM-06); the 3D material is the text ink, so light schemes show a silhouette and High Contrast light no shading at all, and STL and 3MF open sideways (DM-09, DM-10).
12. **The companion overclaims in colour and underclaims in guidance.** Green for a state the app cannot verify, kept through failed saves (CO-02, CO-03); setup as a paragraph with an undocumented deep link (CO-05); the Theme sample under seventeen control rows at the minimum window (CO-04); the conflict scan last, blind to subfolders and to Apple's built-in previews (CO-07); the renderer pill and the scheme gallery depend on contracts decision 026 assumed but did not define (CO-08).

## Blockers

Every Blocker is fixable without a Mac, and each has a test a later Mac run executes.

| ID | Report | Defect | Rule |
|---|---|---|---|

| SP-02 | Security | Comic page labels reach a tooltip without the privacy filter or the hidden-character scan | Privacy |
| SV1 / CH-1 | Structured views, chrome | Table truncation notice claims Source is complete when it is not (data summaries, SQLite schema, partial CSV reads) | Honesty |
| CO-01 | Companion | File Types says it chooses what Finder previews; the repository's own Finder run contradicts it | Honesty, principle 11 |
| DM-01 | Documents | Rendered EPUB, FictionBook and web archives print English adapter labels, machine flags and `[image: …]` markers in every language | Localization |

Majors that behave like blockers for specific users: SV6 / AL1 (VoiceOver reads another row's description in a sorted or filtered Profile), SV4 (YAML outlines re-root compact sequences, shown wrong), DM-13 (any notebook with a figure over about 24 KiB fails entirely), TH-01 (summary JSON drawn as thumbnails), PI-02 (CAD likely broken in the store-signed build), PI-03 (macOS 15 never run; `isolated deinit` may need the 15.4 runtime).

## Corrections to earlier documents

- **Self-audit.** Right in substance on P1–P17 and C1–C15 but understated or wrong in places the reports list: the `.env` chrome is about 230 pt, not 190; the findings banner reaches about 255 pt; P8's fix by reordering `addSubview` would break 32 test lookups; C8 is wrong for two of four citations and misses the General switches; C14's sidebar is a native source list painted opaque, so `.regularMaterial` would not help; 200 % text was never checked offscreen (the attempt failed); word counts are overstated by up to 20; the default footer count is 74, not 76; "Limit: 2 MB" is the output budget, not the input budget; the self-audit has no thumbnail findings.
- **Decision 026.** The list in finding 1 above. In addition: the renderer pill has no catalog source (`presentation` is text or geometry only); the scheme gallery is twelve tiles, not 22, and should be swatches drawn from palette tokens rather than live panes; a fixed 20 pt page title has no macOS text style; labelling Command-comma by destination breaks the standard "Settings…" title; the Theme note "use the saved settings when they next open" overstates (an open preview may be redisplayed); "macOS 15 and 26" are named as validation hosts but the only host is 27.2.
- **Decision 017** says package formats open on Summary; `.ipa`, `.apk`, `.pkg` and torrents open on Files (SV10). **Decision 021** asked the table filter to reuse `OutlineFilterQuery`; it does not (SV8). **Decision 022** draws real CSV, TSV and SQLite rows, which decision 026 rejects citing 022 (TH-05). **Decision 024**'s requests for a unit flag and an unsaturated face count are still open (DM-11). **The interaction record** says live reload keeps the 3D camera; the code resets it (DM-27). **The Finder matrix** reports "structured view unavailable" for a flat YAML fixture that the current parser accepts; re-run before deciding owner question 1.
- **The research reports.** The breadth report calls the shipped provider scanner rule-breaking; AGENTS allows a read-only, bounded scan and decision 023 shipped one, but the sandbox result is unobserved. The closest-rivals report's "Open With → Change All" advice rests on a competitor's support text and nothing shows it decides the Quick Look provider for modern extensions. Owner decision 5 has no sentence to soften: the website makes no STEP exclusivity claim; the real issue is that a default-off format leads the hero and tour.

## The most important opportunities

Ranked by how much they change what users and reviewers see, weighted by what can start now.

1. Fix the six Blockers and the honesty Majors (table notice, File Types subtitle, website attribution and OS copy, ebook labels, citations, URL credentials, page labels). Cloud work, small, testable.
2. Build the verification floor before anyone writes Swift blind: a Linux static gate, a Swift syntax gate, an ownership check, a macOS continuous-integration job that compiles and tests every push, blind-authoring rules, and a pending-verification queue. Cloud work with one Mac run to confirm.
3. Run one Mac session that establishes the facts the program cannot proceed without: the Finder routing matrix on the production identity, measured pane widths and the Tahoe safe area, whether popovers, tooltips and key equivalents reach the remote view, the completion-handler experiment, the macOS 15 symbol check, the thumbnail UTI and system-icon table, the sandbox scan, and a re-baselined benchmark with a CSV case.
4. Amend decision 026 and add the lead's contracts in one commit: ownership, `PreviewFacts` in a UI-free module, a budget-carrying result, `TextOrigin`, `GeometryUnitProvenance`, `OmittedResources`, `muted` and `hairline` with a redesigned contrast test, `NativeStateView`, `PreviewChrome`, an announcer, a copy callback, a command table with key-code matching, plural tooling and a counted string API, and the worker executor and thumbnail admission.
5. Decompose `NativePreviewView` behind named test seams before the seven workstreams branch, so they edit disjoint files.
6. Then run the workstreams in parallel: the seven of decision 026 plus performance, safety, accessibility and localization, platform and thumbnails, each with the items listed in decision 027.
7. Close with the amended gates, the host matrix on macOS 15 and the current release, a TestFlight round (the only way to test the store-signed CAD path), screenshots after the UI settles, and the release items (privacy manifests, OCCT route, store text, deployed pages).

## What this review cannot say

It cannot say how anything looks, sounds, routes or performs. Scores describe what the code says it does; every "needs a Mac" item is a question, not a finding. Competitor comparisons come from the earlier research and remain marketing evidence. Nothing here is a claim about Finder routing, App Review acceptance or translation quality.
