# App Store publishing research for SpacePane

Researched 2026-10-07 (Europe/Istanbul). This report supports the [publishing guide](../release/app-store-publishing-guide.md). It preserves original developer reports, maintainer accounts and Apple DTS responses so a historical workaround is not mistaken for a current requirement.

**Confirmed** means the original reporter or maintainer reports the outcome. **Suggested** means advice was offered without a demonstrated resolution. **Unresolved** means the inspected discussion contains no successful fix. None guarantees the same result on a current SpacePane build. Dates below identify the original event/publication, not a crawler date.

## Corrections of 2026-10-10

Several facts in this report were checked again on 2026-10-10 and are outdated or were incomplete. The report keeps its 2026-10-07 text for the historical cases; these points override it, and the [publishing guide](../release/app-store-publishing-guide.md) carries the same corrections in context.

- **Privacy manifests exist.** The repository now has four `PrivacyInfo.xcprivacy` files: the app, both extensions and the CAD service. The 2026-10-07 statement that none was found no longer holds.
- **No minimum Xcode or SDK for macOS uploads.** Apple's "Upload builds" table lists the macOS app as "Built using Xcode 6 or later" ([Upload builds](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/), [Upcoming requirements](https://developer.apple.com/news/upcoming-requirements/), both read 2026-10-10).
- **App Groups.** Apple's guidance since 2025-02-21 recommends `group.` identifiers for new code. The team-prefixed form used here (`Z743N6D8DS.org.webmeister.spacepane.shared`) remains valid, needs no profile and avoids the macOS 15 container prompt ([Apple DTS](https://developer.apple.com/forums/thread/721701)). The project keeps the team-prefixed form.
- **Age rating.** The questionnaire was replaced in 2026 and also asks about in-app controls, capabilities and social media. Answers are required for new submissions since September 2026.
- **Metadata locales.** App Store Connect offers 50 locales since 2026-03-31. Kurmanji and Hausa are not among them ([App Store localizations](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations)).
- **API key.** An Individual key cannot use provisioning endpoints. Forum reports, unverified, say App Manager keys fail cloud signing, so a Team key with the Admin role is the recommendation.
- **TestFlight signature.** A TestFlight-delivered app is signed with the "TestFlight Beta Distribution" certificate (OID `1.2.840.113635.100.6.1.25.1`, without the Mac App Store marker `1.2.840.113635.100.6.1.9`), measured on a third-party app on this Mac on 2026-10-10. This turns the "distribution signing needs its own CAD test" finding below from a risk into a known defect, which was fixed in source on 2026-10-10 (the requirement now has three branches) and is unproven on a SpacePane build. The TestFlight leaf certificate's organizational unit reads the literal `TESTFLIGHT`, never a team, so the team branch cannot match it.
- **Owner statements, 2026-10-10.** The App Store Connect app record and API key exist; the price is set in App Store Connect (roughly USD 9.99, local pricing adopted); the contact address is `info@spacepane.com`. These are not checked against the account.

## Findings that change SpacePane's release plan

- **Distribution signing needs its own CAD test.** The service's current client rule checks the leaf certificate's developer Team ID. Apple's Store signing differs. Treat rejection of an Apple-delivered client as a risk to investigate, not a reproduced failure. (Corrected 2026-10-10: reproduced for TestFlight against another vendor's app; see the corrections above.) The guide contains the exact read-only probe and acceptance gate. [Service source](../../Native/CADImportService/main.swift), [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements).
- **The dependency license gate remains open.** The repository's static OCCT audit explicitly requires a reviewed source/relinking distribution route; default-off functionality does not remove shipped code. [CAD dependency audit](../dependencies/occt.md).
- **Current breadth exceeds historical host evidence.** The integrated 76-format catalog must not inherit the earlier 22-format Finder matrix as if it were current validation. [Parity record](../validation/parity-program-2026-10-05.md), [earlier matrix](../validation/finder-matrix-2026-10-04.md).
- **The website is live but its contact is stale.** On October 7, both legacy support/privacy URLs redirected and returned HTTP 200. Browser inspection of the rendered English pages confirmed `support@spacepane.com`, which must be reconciled with the owner's active `info@spacepane.com`. No mailbox message was sent. [Support](https://spacepane.com/support), [privacy](https://spacepane.com/privacy).

## Important platform caveat: do not turn an iOS-only upload error into a macOS rule

A February 2024 developer [reported `QLSupportedContentTypes` asset validation rejecting `public.jpeg-2000`](https://developer.apple.com/forums/thread/745820) for an **iOS/iPadOS** app whose proprietary `.JPX` files collided with JPEG-2000. The author says DTS confirmed the behavior and had no solution; the private DTS response itself is not public. This does **not** establish a blanket prohibition on macOS Quick Look declarations of system types. SpacePane must validate its actual macOS export and preserve the one deliberate preview-only `public.data` extensionless exception in its own decision record. Never fix a validator/routing error by claiming ownership of another developer's type or modifying a signed manifest after export.

## Limits on applying these precedents

No well-sourced Quick Look minimum-functionality rejection with a confirmed remedy was found in this pass. The guide therefore uses current Apple rules and SpacePane's actual useful settings/sample interface, rather than inventing a 4.2 rejection story. No confirmed native-Mac-only screenshot or translation rejection was used as evidence either.

The February 2025 [missing privacy manifest discussion](https://developer.apple.com/forums/thread/774714) is mainly an iOS case and contains no confirmed fix in the inspected exchange. A dependency named GoogleToolboxForMac does not make it a native macOS case. The guide separates App Privacy labels, manifest packaging, listed-SDK rules and the current platform scope of required-reason APIs.

Unanswered reports can identify valuable tests. They cannot establish an Apple-approved workaround. In particular, SpacePane's XPC design is supported by its own [CAD host validation](../validation/cad-previews-2026-10-04.md), not by a solution in the unanswered external-helper thread.

## Evidence boundary

This work reviewed source/configuration and public documentation, and performed read-only website checks. It did not build a new archive, inspect a distribution profile from the owner's account, verify mailbox delivery, install a TestFlight build, test Finder on macOS 15, resolve the license gate or obtain App Review approval. Those remain concrete actions in the guide, not completed findings.
