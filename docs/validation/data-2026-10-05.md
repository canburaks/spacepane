# Data formats — 2026-10-05

Validation record for [decision 018](../decisions/018-columnar-scientific-and-geo-data.md): Parquet, Avro, Arrow IPC,
NumPy arrays and archives, HAR, GeoJSON, GPX, KML/KMZ and the SQLite schema grid. Tested machine: Apple silicon,
macOS 27.2; Xcode 27.0 / Swift 6.4 / SDK 27, Swift 6 strict concurrency (`-default-isolation nonisolated`),
deployment target macOS 15. A deployment target is not macOS 15 runtime evidence.

## What was and was not verified

Verified locally: parsing, bounds, cancellation, concealment, no-source-mutation, localization resource completeness,
native view behavior in an unsigned test process, and the typed catalog/manifests. **Not verified:** Finder routing of
any of these types (including which provider macOS selects, and the imported-type declarations on macOS 15), observed
Finder previews or thumbnails, the thumbnails workstream's drawing of these formats, VoiceOver and keyboard behavior in
a signed host, translated layouts, native-speaker review of the 107 new strings (drafts), release performance on
recorded hardware, and behavior in the signed, sandboxed extension. The Plot, Rows and Table views were exercised only
through the package's unsigned AppKit test harness.

## Observations and limits

- Default budgets: HAR, GeoJSON, GPX and KML are read whole and fail as `inputTooLarge` above 1 MiB; the user-adjustable
  file-size limit raises this. Parquet, Avro, Arrow, NumPy and NPZ read only footers, headers and the first pages.
- A 20,000-feature GeoJSON, a 20,000-point GPX, 4,000,000-element deflated NumPy members and the wide-table cases ran
  inside their 30 s test deadlines in a Debug build (the whole 647-test run took about 5 s). No per-format timing and no
  Release benchmark was recorded, so the plan's performance budgets remain unmeasured for these formats.
- Parquet row sampling spends at most half of the input budget; with a 700-byte budget the footer summary still renders
  without rows (tested).
- The `database.sqlite` summary's new `table` member is localized in Table mode and its column headers, but its key in
  the Summary tree is shown as written, because the pre-existing `database` label set matches SQLite first (request 1).
