# Archive listings validation — 2026-10-05

Evidence for [decision 013](../decisions/013-archive-listings.md) (RAR, 7z, bzip2, xz, Java archives and
TAR dates). Environment: macOS 27.2, Xcode 27.0 (Swift 6.4, macOS 27.0 SDK), Apple M5 Pro (arm64),
Debug configuration, worktree branch `parity/archives`. Package-level and corpus evidence only.

## What was not verified

Finder routing of `.rar`, `.7z`, `.bz2`/`.tbz`/`.tbz2`, `.xz`/`.txz`, `.jar` and `.war` (declared or resolved
types, preview and thumbnail surfaces); thumbnails (policy is `generic`, the glyph belongs to the
thumbnails workstream); VoiceOver, keyboard behavior and translated layout of the new summary labels;
native-speaker review of the 15 new draft translations; a signed installed build, an Xcode bundle build
(`-lbz2` linking of the new C target under Xcode, resource embedding) and `qlmanage`. No performance
measurement in Release was taken; the budgets are targets. Nothing was run against real-world RAR files:
none was available, and the RAR layouts were cross-checked with libarchive instead (below).

## Independent cross-checks (outside the repository; not shipped)

- **libarchive (`/usr/bin/bsdtar`).** The Python builders in `script/archive_fixtures.py` were checked by
  listing their RAR 4, RAR 5 and plain/LZMA/LZMA2-header 7z output with bsdtar: names, sizes, directories and
  the 2026-01-01 dates matched, and bsdtar rejected an early RAR 5 directory entry that lacked a data-area
  field, which the builder now writes as real archivers do. The Swift fixture builders in the tests mirror
  the Python ones and the reader was run against both.
- **py7zr 1.0.0** (installed in a throwaway virtual environment) wrote the four archives embedded as test
  vectors; the reader listed them and matched their names, kinds, sizes and encryption flags. It is
  LGPL-2.1-or-later and is used only as an external generator: nothing of it is copied, linked or shipped.
- **liblzma through Python `lzma`** produced the raw LZMA, LZMA2 and xz vectors (including the 64 MiB
  dictionary and multi-block cases made with the `xz` command-line tool); each vector is decompressed again
  by the generator before it is written. `bzip2`/Python `bz2` produced the bzip2 vectors.
- **Debug timing.** A 9,000-entry 7z (LZMA and LZMA2 headers) listed its first 1,814 entries with
  `partial: true` in about 0.2-0.45 s in the Debug build; 9,000-entry RAR 5 and RAR 4 archives listed the same
  1,814 entries with `partial: true` (untimed). No Release timing was taken.

## Adversarial corpus (the four new formats)

Each new format contributes one synthetic seed (`31-listing.rar`, `32-listing.7z`, `33-content.bz2`,
`34-content.xz`, with a secret-like entry name or secret text) and the corpus's eight variants of it: the
original plus seven mutations (empty, one byte, half prefix, missing last byte, seeded bit flip, seeded
maximum word, seeded invalid prefix). Every original is `ready`; every mutation is `unavailable.malformedDocument`; no case crashed,
exceeded a budget or changed the source files, and the synthetic secret never appeared in a presentation.
