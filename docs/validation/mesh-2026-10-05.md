# Mesh formats validation

Date: 2026-10-05, Europe/Istanbul. Host: Apple M5 Pro (18 cores), 48 GiB, macOS 27.2 (26B5091g); Xcode 27.0 (27A266a), SDK 27.0, Swift 6.4. Product minimum remains macOS 15; nothing here establishes macOS 15 or Intel behaviour. Design and limits: [decision 024](../decisions/024-mesh-formats.md).

## What was and was not verified

Verified: pure-Swift parsing of STL (binary, ASCII), OBJ, PLY (ASCII, little- and big-endian binary) and 3MF into the neutral mesh; the pipeline's classification, file-type policy, budgets, cancellation and outcomes; catalog, manifest, localization-resource and sample consistency; deterministic mutation of the host fixtures; parse time for synthetic models.

**Not verified:** Finder routing, which provider Finder uses for these types, Quick Look preview or thumbnail invocation, rendering in the signed preview extension or companion (Metal drawing of these meshes was not run), VoiceOver and keyboard behaviour of the geometry view for these formats, behaviour on macOS 15 or Intel, performance inside Finder, and native-speaker review of the new strings. The Xcode build, the signed app, `qlmanage`, `pluginkit` and Finder were not touched. The geometry viewer and `PreviewMesh` validation are the existing, separately tested CAD path.

## Corpus and fixtures

`script/generate_host_fixtures.py` now adds nine synthetic files numbered 101 to 109 (binary STL with a "solid" header, ASCII STL, two OBJ, three PLY encodings, two 3MF including a composed inch model). Four of them carry the synthetic secret in a header, comment or title; none surfaces it, because a geometry outcome has no text. The deterministic adversarial corpus mutates each fixture eight ways (empty, one byte, half, last byte missing, bit flip, maximum word, invalid prefix, original): the 72 mesh cases ended as `geometryReady` (19) or typed `malformedDocument` (51), `unsupportedFormat` (1) and `outputTooLarge` (1), with no crash and no source change. All nine originals are `geometryReady`. The harness `Tests/Integration/AdversarialCorpusChecks.swift` needed a minimal edit to accept a geometry outcome for a format whose ID matches.

`script/generate_appearance_samples.py` adds one torus sample per format (under 25 KiB each), which the Theme page opens through the same pipeline. The companion model check skips geometry samples because CAD import needs a helper; mesh samples were not rendered.

## Parse time

Synthetic torus models built by the performance suite, parsed with the adapter directly (not through Finder, not including file I/O), one run each on the host above. Peak resident size is the whole test process, including every fixture, so it bounds rather than isolates the parser.

Release (`swift test -c release -Xswiftc -enable-testing --scratch-path Packages/PreviewCore/.build/mesh-release --filter parsesAHundredThousandTrianglesInEveryFormat`), 100,000 triangles, 50,000 vertices:

| Format | Input | Parse |
|---|---:|---:|
| STL binary | 4.8 MiB | 13 ms |
| STL ASCII (compact numbers) | 12.1 MiB | 30 ms |
| OBJ | 2.2 MiB | 9 ms |
| PLY ASCII | 2.1 MiB | 9 ms |
| PLY binary | 1.4 MiB | 6 ms |
| 3MF (deflate) | 0.75 MiB | 212 ms |

Process peak resident size: 130 MiB.

Largest inputs the contract admits (`--filter parsesTheLargestAdmittedInputs`), Release: a 16.0 MiB binary STL (334,560 triangles) parsed in 55 ms; a 3.7 MiB 3MF with 500,000 triangles (about 32 MB of XML) in 1,344 ms; process peak 270 MiB.

Debug (the `--test` configuration, same suite): 100,000 triangles in 524 to 1,139 ms for STL, OBJ and PLY and 759 ms for 3MF; the 16.0 MiB STL in 1,805 ms and the 500,000-triangle 3MF in 5,781 ms; process peak 328 MiB. Debug numbers are not a performance claim.

These are single observations on one machine. They justify default-on in the decision record; they are not percentile benchmarks, cold-versus-warm measurements or Finder latency, and the product's existing performance targets remain unmeasured by this work.

## Known limits and observations

- `faceCount` saturates at the contract's 100,000 for STL and 3MF models above 100,000 triangles; the viewer's "Faces" figure is then a floor while "Triangles" stays exact.
- STL, OBJ and PLY dimensions are shown in a viewer that always labels millimetres; the source carries no unit.
- The system Quick Look 3D extensions found on this host (`com.apple.HydraQLPreviewExtension`, `com.apple.HydraQLThumbnailExtension`) declare the three system mesh types; see the decision record for what that does and does not imply. Nothing was observed about which provider Finder selects.
- A malicious or damaged archive can still make `XMLParser` do work between checkpoints; the checkpoints run every 4,096 nodes and the byte, node and decoded-size ceilings are enforced first.
