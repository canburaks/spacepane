# Native diagrams validation — 2026-10-05

Evidence for [decision 016](../decisions/016-native-diagrams.md): Mermaid (`text.mermaid`) and draw.io
(`data.drawio`) previews drawn natively. Everything below ran from the `parity/diagrams` worktree with the Command
Line / Xcode toolchain on this Mac (Swift 6.4, `swiftlang-6.4.0.34.1`, macOS SDK selected by `xcode-select`:
`/Applications/Xcode.app/Contents/Developer`), in Debug configuration.

## Visual inspection

While developing, each diagram type (flowchart in two directions, sequence with frames and notes, pie, state with a
composite state, class, entity-relationship, and a draw.io page with a swimlane, cylinder and elbow edge) was rendered
through `SafeDiagram.draw(in:size:palette:)` into PNGs in light and dark palettes and read back for inspection. Text was
upright and inside its shapes, frames enclosed their members, arrowheads sat on the correct ends, and class and
entity line ends were recognizable. The temporary render test was deleted; the committed pixel tests are the
automated version of these checks (ink present, text inside its node, palettes honoured, flipped contexts identical).

## Not verified

- Finder routing, provider priority or the declared imported types for `.mmd`, `.mermaid`, `.drawio` and `.dio` in a
  signed, installed build; `qlmanage` and `pluginkit` were not run.
- Thumbnails: the catalog marks both types `content`, but no thumbnail was produced or observed.
- VoiceOver: the accessibility group, children, roles and frames are asserted through AppKit accessibility APIs in
  tests, never spoken or navigated by VoiceOver. In particular `accessibilityFrameInParentSpace` for children of a
  flipped view is unconfirmed.
- Native-speaker review of the 26 new strings in 13 languages (drafts only); layout of long translations in the
  view was not checked visually.
- Behaviour in the signed Quick Look extension host (sandbox, Metal-free Core Graphics drawing, memory) and the
  performance budgets in Release configuration. Layout timing was only bounded loosely in Debug tests (a 2,000-node
  chain and a 5,000-edge graph each laid out in well under a second on this machine).
- Interaction with real trackpad pinch and scroll events: pinch (`magnify`) and scroll handlers exist but tests call
  the zoom and pan functions directly.
- Fidelity against mermaid.js and diagrams.net: layouts are readable, not identical.
