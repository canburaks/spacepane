## What the checks cover

**Package tests added (40 test functions, 95 cases, in `Settings/` folders).**

- `SchemaSixMigrationTests`: schema 6 round trip of every new field and both schemes; documented defaults; schema 5 migration with strict syntax-style and profile decoding (including profile ID, name and its own appearance); every earlier schema (1 to 5) defaulting only what it lacked, without writing the file; each missing schema 5 syntax or profile field failing closed; each missing or wrongly typed schema 6 behavior or scheme field failing closed; out-of-range `folderDepth` (0, 5, -1, 99, `Int.max`, 1.5, text); unknown, mismatched-polarity and wrong-case scheme names in the main style and in a profile; invalid saves rejected with the saved file unchanged; resets leaving behavior alone; a near-maximum document (32 profiles with long names, all roles styled, 500 overrides) inside the 64 KiB bound.
- `ColorSchemeContractTests`: scheme polarity and picker contents; stable raw values; style validity; strict style decoding; theme exchange version 2 round trip for every scheme, version 1 files importing as Standard, version and shape mismatches, unknown or mismatched schemes, extra fields; export of an invalid scheme refused; a theme applied to a snapshot leaving file-type and behavior choices alone.
- `ColorSchemeContrastTests`: WCAG 4.5:1 for the foreground and all twelve roles of every scheme in every appearance it can be chosen for (12 palettes: Standard for both appearances, four light schemes and six dark ones), computed independently of the production code; 7:1 for the high-contrast palettes; background polarity; Standard's values pinned independently; published backgrounds and foregrounds; schemes distinct and not collapsing to few colors; polarity fallback; the text palette applying the scheme of the effective appearance (explicit and system); High Contrast and Increase Contrast overriding every scheme choice; color opt-out keeping the scheme background; the style pass and a rendered text view carrying scheme colors with the displayed characters unchanged.
- `GeometryColorSchemeTests`: the geometry viewport background following the scheme and appearance.
- Existing preference tests were updated for schema 6 (current document, version assertions, the historical Enable All matrix extended to schema 6, new fields added to the missing-field matrix). Existing appearance tests are unchanged and pass.

**Isolated model checks added (`Tests/Integration/SettingsModelChecks.swift`, run from `CompanionModelChecks`).** All use a temporary directory created for the run.

1. Behavior choices persist in one snapshot, a fresh reader observes them, folder depth clamps to 1 through 4 in the model, repeated values do not publish, and a behavior change is not an appearance edit.
2. Scheme choices persist; a scheme for the wrong appearance is ignored; profiles restore schemes; Reset Appearance restores Standard and leaves behavior and file-type choices; theme round trip.
3. A schema 5 file migrates through the companion store without being written, and the first save publishes schema 6 including the migrated profile.
4. An out-of-range stored depth recovers fail-closed and an explicit choice repairs storage without re-enabling file types.
5. The provider scan over synthetic bundles: overlap by equal identifier, case-insensitive identifier, conformance (a Swift source type conforms to this app's plain-text and source-code types), and notebook conformance to `public.json`; preview and thumbnail kinds merged per app; abstract roots matching only exactly; unrelated, wrong-extension-point and extension-free apps scanned but not reported; the app's own identifier excluded; malformed plist falling back to the file name; non-app entries and a deeper level ignored; a missing folder skipped silently.
6. Scan bounds and safety: a symbolic-linked app, a symbolic-linked `PlugIns` folder and a symbolic-linked `.appex` all ignored (the linked `PlugIns` case first failed because a trailing slash made `lstat` follow the link, and was fixed); an extension plist over the cap skipped; a bundle without `Contents` counted as skipped; the application limit stopping the scan and being reported; a folder with no read permission reported by name while the readable folder is still scanned (skipped when the run is privileged); the standard roots are exactly the three documented folders.
7. Cancellation: a task cancelled before it enters the scanner stops at the first checkpoint, and a later scan completes.
8. The diagnostics model: starting shows the scanning state at once; only the latest scan publishes and a late result from a replaced scan is dropped; cancel returns to the starting state and a cancelled scan never publishes; a failed scan shows no partial result.

## Not verified

- **The real window.** No page was shown on screen. The General, Theme and About layouts, the scheme pickers, the stepper, the scan section's states and long translated text were not rendered or inspected, offscreen or live. Typechecking proves the views compile, not that they look right.
- **VoiceOver, Full Keyboard Access, large text, Increase Contrast and Reduce Motion at runtime.** Labels, hints and combined elements were written to the existing patterns and are not read by any assistive technology. Increase Contrast overriding schemes is verified in the palette and in package tests, not in the running companion.
- **Translations.** 47 new keys exist in all 14 languages as drafts and pass the key and placeholder checks. None was reviewed by a native speaker, and OS pane names in the provider guidance follow the macOS wording where recalled from memory and are English for languages macOS does not ship. Translated layout was not checked.
- **The scan in the signed sandboxed app.** The scan was exercised only over synthetic bundles in a temporary directory. Whether the sandbox lets the signed companion list `/Applications`, `/System/Applications` or `~/Applications`, or read bundle property lists, was not tested; the code reports what it cannot read, but that path is also untested under the sandbox. Behavior over real installed apps, including very large or unusual bundles, was not measured, and no performance figure is recorded.
- **Real extension behavior.** Both Quick Look extensions read the same snapshot, but no Finder-hosted request was observed using the new folder options, reload choice, thumbnail choice or schemes. `reloadsOnFileChange` and `showsContentThumbnails` are persisted and exposed; the interaction and thumbnails workstreams must consume them, and the CAD viewport follows a scheme only after the host sets `NativeGeometryPreviewView.syntaxStyle` (see the decision's integration notes).
- **Palette provenance.** Upstream values were read from the upstream files on 2026-10-05 by network fetch. The license texts were not diffed byte for byte; the notice records each upstream's license name and copyright line as read.
- macOS 15 runtime, Intel and the baseline minimum OS are unchanged by this work and were not checked.
