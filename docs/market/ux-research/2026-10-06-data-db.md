### Observations by rubric dimension
1. **Preview anatomy — 4/5.** Title bar with file icon and name, then a ~28 pt second strip: left "api-events.jsonl · 60 records · 12 KB" (name, count, size), right a four-segment control Pretty / Tree / Compact / Raw with the active segment filled system blue. Everything else is content. An error ribbon slides in under the strip, full width, red-tinted, with a cross glyph. Only one row of chrome: a good weight ratio.
2. **Content presentation — 4/5.** Monospaced text on near-black, dim right-aligned gutter with a hairline divider. Keys blue, strings red, numbers orange, booleans magenta. JSONL records are separated by a dim rule labelled "#1", "#2" so a log reads as discrete entries. Tree rows show no indent guides, only chevrons; collapsed or container nodes carry counts in braces ("{8 keys}", "[2 items]"). Compact mode wraps mid-token (a path string breaks as `/api/users/me` + `"`), which looks rough.
3. **Interaction & discoverability — 3/5.** Site text (not in screenshots) says ⌘F finds inside the preview, ⌘G / ⇧⌘G step, with a match count; right-click Copy Value / Copy Key / Copy Key Path / Open URL exists in Tree. The Tree and Compact segments are visible but locked behind Pro, so the free user sees the control and learns about the lock only by clicking (inferred from the unlock sheet copy; behaviour not shown).
4. **States & honesty — 5/5.** Best in cluster on wording: bad records flagged inline with exact line and column while the rest keeps rendering ("never a blank preview"); a site claim that huge files read only the head and "a banner says exactly how much you're seeing" (banner **not shown** in any screenshot). Ribbon states "first 4 records" so the count scope is honest.
5. **Companion / settings app — 2/5.** Only the Pro unlock window is shown: a small non-resizable window with a title "JSON Loupe Pro", three icon rows (Tree view, Compact view, Viewer window), one full-width blue pill "Unlock Pro — $4.99", Restore Purchases link, and a grey footnote "One-time purchase. No subscription, no account, no tracking." No settings, onboarding or extension-enablement UI shown.
6. **Visual identity & native feel — 3/5.** Dark-only in all captures; system segmented control, SF text, standard traffic lights. Light mode and a Finder-sized Quick Look frame are not shown (the shots are a plain app-style window, not the Quick Look chrome).
7. **Trust & privacy — 3/5.** "Nothing leaves your Mac / No network access / Sandboxed and read-only" is website copy and the unlock-sheet footnote; no in-preview indicator. No secret masking anywhere in the material.
8. **Delight and friction — 3/5.** Delight: record separators, error markers, one-line "Press Space. Actually read it." copywriting. Friction: paywalled modes shown in the free control; Compact wraps awkwardly.

### Worth matching or beating
- One slim strip: name · record count · size on the left, mode segmented control on the right.
- Inline per-record error markers with exact column while the rest renders, plus a ribbon summarising scope ("1 of the first 4 records").
- Counts on container nodes in Tree (`{8 keys}`, `[2 items]`) so collapsed nodes are informative.

### Mistakes to avoid
- Showing locked modes in the free control (SpacePane has no tiers; every mode should be live).
- Mid-token wrapping in a compact view; wrap at structure boundaries or scroll.
- Declaring a head-only read only on the website; the notice must be in the preview itself.

### Observations by rubric dimension
1. **Preview anatomy — 4/5.** Real Quick Look chrome visible: close/zoom glyphs, title, share button, and "Open with TextEdit". Below, a centred segmented control (Pretty / Raw / YAML) and, right, a "Pretty Text" checkbox plus a copy-to-clipboard icon button. Two rows of chrome above content (~64 pt in the capture); the options row is dense but all controls are real SwiftUI/AppKit controls.
2. **Content presentation — 4/5.** Small (~11 pt) monospaced text on white, dim gutter with a darker divider. Strings navy, numbers brown, booleans purple, comments grey. Collapse chevrons sit right of the line number; collapsed regions show `{ ...` without counts. In JSONL the first gutter is the record index and the second the formatted line number, so "20034" and "1542" are both visible. Long strings with real line breaks are hung-indented under the opening quote, which reads like a paragraph.
3. **Interaction & discoverability — 4/5.** Copy button always present; YAML tab converts then copies ("Switch to the YAML tab, hit Copy, paste it anywhere"); folding via gutter chevrons. Search is not shown in screenshots; shortcuts not shown.
4. **States & honesty — 2/5.** A "5 MB" ceiling is only in screenshot copy; no truncation notice, error state or empty-file state is shown anywhere.
5. **Companion / settings app — 1/5.** Not shown.
6. **Visual identity & native feel — 3/5.** Looks like a genuine Quick Look panel; full light and dark pair shown (dark uses a blue-black ground, not pure black). Marketing frame is a purple gradient unrelated to the product.
7. **Trust & privacy — 1/5.** Headline "Safe for secrets and tokens" sits over a preview that prints a full PEM private key unmasked (demo value). Privacy is asserted by slogan ("No network. No web view. Sandboxed.") while the UI makes no effort to protect the viewer.
8. **Delight and friction — 4/5.** "Pretty Text" is a memorable micro-feature: one checkbox turns `\n` escapes into real breaks. Friction: Raw view clips instead of wrapping; fold placeholders carry no counts.

### Worth matching or beating
- A single, labelled option toggle for escaped text ("Pretty Text") that changes presentation only and never edits source.
- Dual line numbers for JSONL (record index and formatted line).
- Always-visible copy icon at the right of the options row.

### Mistakes to avoid
- Showing a private key while claiming "safe for secrets" (our default masking is the opening).
- Fold placeholders with no counts or size hint.
- Clipping long Raw lines with no horizontal-scroll or wrap cue.

### Observations by rubric dimension
1. **Preview anatomy — 3/5.** The strongest unit is the coloured banner carrying one fact ("4 tables", "6 cells · python"), sitting directly above content with the same footprint on every format; format colour (teal for SQLite, blue for notebooks) is the identity. 8. **Delight and friction — 3/5.** Delight: the diagram and the one-glance banner. Friction: Pro splits schema export, ER diagram and CSV export from the free tier; thumbnails promise "real data" (see mistakes).

### Worth matching or beating
- A per-format coloured count banner that gives the one number that matters ("4 tables") in thumbnail and preview alike.
- Schema diagram vocabulary: key glyph for PK, arrow glyph for FK, right-aligned dim type names, a different header tone for views.
- Stating the no-write guarantee in concrete mechanics (no sidecar files created).

### Mistakes to avoid
- Putting real row values on Finder thumbnails; our privacy rule keeps sensitive content out, so show names, counts and shape only.
- Truncating headers to "recipe…" with no tooltip or width control.
- Leaving the real Quick Look controls out of marketing images so nothing can be judged.

### Observations by rubric dimension
1. **Preview anatomy — 4/5.** Richest anatomy here. Below the Quick Look title bar sits an app-branded strip (bold "Quick Data Insights" with a small icon, a grey duplicate name, and the words "Quick Look" at far right) that consumes ~40 pt and repeats information. 5. **Companion / settings app — 4/5.** A genuine single-window sidebar app (Overview, Supported files; section "Setup" > How to Enable) with a green status card: "App is in Applications" and the next step spelled out as "enable ... under System Settings → Privacy & Security → Extensions → Quick Look", plus a "Refresh install status" button. 6. **Visual identity & native feel — 3/5.** Native sidebar, SF type, system blue. The Quick Look content area is a flat light grey that feels slightly dated; companion cards are polished. Dark mode not shown.
7. **Trust & privacy — 4/5.** A dedicated "Offline by design" card in the companion ("does not use the network"; KaTeX, Plotly and Markdown rendering ship inside the app). It is the only app in the cluster that puts a privacy statement inside its own UI.
8. **Delight and friction — 3/5.** Delight: Integrity OK, copy-as-SQL/.py buttons, cell chips "#1 MARKDOWN". Friction: duplicated branding strip, unexplained "(int96)" cells, inspector keeps its full width even when the data grid needs the space.

### Worth matching or beating
- Inspector card with label/value pairs plus one prominent copy action, same skeleton across formats.
- Schema screen structure: Foreign keys as "from → to" rows, Pragmas, Tables with right-aligned row and column counts.
- Companion status card that spells out the next step and offers "Refresh", paired with an "Offline by design" card.

### Mistakes to avoid
- A brand strip inside the Quick Look body that repeats the app and file name.
- Printing a raw type token ("(int96)") as a cell value instead of a clearly styled "unsupported type" cell.
- Telling the limit ("first 100 rows") only in the companion rather than in the preview.

8. **Delight and friction — 2/5.** One-click "Open Extension Settings" is the standout help; the duplicated header strip and proportional-font tree are friction.

### Worth matching or beating
- A primary "Open Extension Settings" button next to "Refresh" in the companion (SpacePane has the destination already; keep wording honest).
- Small grey count badges "{ 3 items }" after container keys.
- "Reveal App" as a recovery action when the extension does not appear.

### Mistakes to avoid
- Claiming "Installed Correctly" for a state that only means the app is in Applications.
- Unmasked `.env` secrets in the headline screenshot.
- A proportional font for a tree that must align values and numbers.

## Cluster synthesis

### Patterns most apps share (table stakes)
- A dark and light syntax palette with keys in blue, strings in a warm colour, numbers orange/brown and booleans purple.
- A gutter with dim line numbers; JSONL treated as records, not one line.
- A mode switcher as a native segmented control (Pretty/Raw/YAML, Data/Schema/Diagram) rather than tabs inside a web view.
- A visible copy action (icon button or inspector button).
- Row-count style facts in a header or inspector ("60 records", "8715 rows").
- "Local / offline / no network" stated in marketing copy.
- A sidebar companion with an "is it installed" status card (Quick Data Insights, FinderPeek).

### Patterns only one or two apps have that users would notice
- Inline error markers with exact column and an "N of first M records failed" ribbon (JSON Loupe).
- "Pretty Text" escaped-newline expansion (QLook JSON).
- Dual gutters (record and line) (QLook JSON).
- Inspector card with a single copy action per format (Quick Data Insights).
- Schema screen of FK rows, pragmas and table counts (Quick Data Insights) and ER diagram (Fast SQLite Viewer, Quick Data Insights).
- Per-row type glyph, right-aligned type/count column and path bar (OK JSON, not Quick Look).
- Floating pill buttons showing shortcuts (Peek).
- Immutable-open mechanics stated concretely (Fast SQLite Viewer).
- "Offline by design" card inside the app (Quick Data Insights).

### Where every app in this cluster is weak (our opening)
- **No secret handling at all.** QLook JSON prints a PEM private key under "Safe for secrets", FinderPeek prints `.env` secrets; none shows a mask, a count of hidden values or a reveal control.
- **Large-file honesty in the preview itself.** Only a website sentence (JSON Loupe) and a companion card (Quick Data Insights); no screenshot shows a "showing 100 of N" or "read first X MB" notice inside the preview.
- **Typed, explained cells.** No Quick Look grid shows type badges, column stats, sticky-header evidence or an "unsupported type" cell style; Quick Data Insights prints "(int96)" as data.
- **Tree affordances in Quick Look.** Tree is Pro-gated (JSON Loupe) or plain (FinderPeek); no path bar, no type column, no per-type icons in any Quick Look extension (those exist only in OK JSON).
- **Localization and accessibility are never evidenced** (language count, VoiceOver, keyboard focus order); OK JSON alone claims 12 languages.
- **Companion theme editing and per-type toggles with live preview** appear nowhere in this cluster.
- **Thumbnails:** only a claim that SQLite thumbnails show real data; none shows a safe, shape-only thumbnail.

### Ten ranked recommendations for SpacePane
1. **One slim strip: facts left, mode control right.**
   - What: a ~28 pt row under the Quick Look title bar with "name · N records · size" (or "N tables · size") on the left and a native segmented control (Rendered/Tree/Raw, Data/Schema) on the right; no brand strip.
   - Why: JSON Loupe's single row scores best on weight; QDI and FinderPeek waste ~40–50 pt on repeated names.
   - Rules: native AppKit/SwiftUI control; every label localized; facts are counts from the bounded read, not claims about the whole file.
   - Cost: S/M.
2. **Tree rows with type glyphs, counts and a right-aligned type column.**
   - What: per-row SF Symbol for string, number, boolean, null, URL, array and object; "{8 keys}" or "[2 items]" on every container; a quiet type word at the trailing edge.
   - Why: OK JSON's rows are the most scannable; JSON Loupe and FinderPeek confirm count badges are enough on collapsed nodes; JSON Loupe's tree has no guides and FinderPeek's uses a proportional font, so alignment is a gap.
   - Rules: accessible labels for glyphs in all 14 languages; colour never the only cue; semantic hints stay separate from format identity.
   - Cost: M.
3. **Path bar with copy for the selected node or cell.**
   - What: a footer breadcrumb (`$ › orders › 0 › tracking_url`, or `table › column › row`) with Copy Path; right-click Copy Key / Value.
   - Why: OK JSON's synced path bar and JSON Loupe's right-click copy (locked behind Pro there) are the strongest lookup aids.
   - Rules: Copy Value must respect redaction (copy the mask unless the user has revealed it); no source mutation.
   - Cost: S/M.
4. **Inline failure markers and an in-preview scope ribbon.**
   - What: a ribbon stating the scope ("Read the first 5 MB of 212 MB", "1 of the first 4 records failed to parse") and exact line/column markers in the content; the rest keeps rendering.
   - Why: JSON Loupe is the only app that models this; nobody shows head-only notices in an actual screenshot.
   - Rules: use typed safety-finding kinds with counts (no source values); honest wording, localized, plural-aware.
   - Cost: S.
5. **A quiet, readable grid.**
   - What: sticky header, ~24 pt rows with faint zebra, dim row-number gutter, right-aligned numerics, a dim "NULL" word, ellipsis truncation with the full value in the inspector, footer "rows 1–100 of 55,991 · 3 selected".
   - Why: TablePlus's restraint beats QDI's 34 pt-pitch grid and FinderPeek's centred, rule-only table; no Quick Look app shows a selection or range footer.
   - Rules: bounded rows; read-only; selectable text; both appearances; VoiceOver table semantics.
   - Cost: M.
6. **Inspector card with one primary copy action.**
   - What: a collapsible trailing card with label/value pairs (Tables, Rows (shown), Integrity, Size) and one button (Copy schema, Copy as SQL), plus per-field type labels like TablePlus's Details pane.
   - Why: QDI uses one skeleton for three formats; TablePlus puts types in the inspector so the grid stays calm.
   - Rules: read-only inspection only; never run SQL or code; collapsible so the grid keeps the width at small Quick Look sizes.
   - Cost: M.
7. **Shape-only thumbnails with a count banner.**
   - What: a coloured per-format banner ("4 tables", "212 records") over a mini grid or tree skeleton showing column names, keys and counts, never cell values.
   - Why: Fast SQLite Viewer and Python Data Viewer prove a banner-plus-grid thumbnail is recognisable; their "real data" claim breaks our privacy rule.
   - Rules: sensitive content out of thumbnails and caches; names only after the same redaction filter; safe for the companion's appearance profiles.
   - Cost: M.
8. **JSONL record separators, dual gutter and a "Pretty text" toggle.**
   - What: dim "— #12 —" rules between JSONL records, both record and logical line numbers, and an option to expand escaped `\n` for display.
   - Why: JSON Loupe's separators and QLook JSON's dual gutter and Pretty Text are the most-loved log features in this cluster.
   - Rules: logical line numbers describe the concealed displayed text and sit outside selectable text; expanding escapes is presentation only and must not reveal concealed characters.
   - Cost: M.
9. **Visible find and shortcut affordances.**
   - What: a find bar with "3/12" count and ⌘G stepping (JSON Loupe, OK JSON) plus a small labelled "Find ⌘F" pill when idle (Peek's floating shortcuts).
   - Why: shortcuts in the cluster are discoverable only in marketing text except Peek and TablePlus, which print them beside controls.
   - Rules: keyboard-first and VoiceOver-labelled; works over selectable text without altering it.
   - Cost: M.
10. **Companion status and limits cards, with honest wording.**
    - What: on General, a status card in QDI/FinderPeek style with the next step and Refresh, but worded as "Settings saved here" (never "Installed Correctly" or "Finder uses SpacePane"), plus on File Types a one-line limit under data formats ("reads the first 100 rows") and an "Offline by design" line.
    - Why: QDI and FinderPeek show the status-card pattern works; QDI's per-format limit sentence is the only place it tells users what bounded means.
    - Rules: companion status text reports where settings are saved, never that Finder uses this provider; every string localized; no third-party status APIs.
    - Cost: S.
