# Expansion research: scientific, statistical, geospatial, biological and medical data

Researched 2026-10-13 (Europe/Istanbul). Angle 6 of 11 parallel agents; the lead synthesises. Audience for this angle: researchers, analysts, students and lab staff.

## 2. Key findings

1. **Licence is not the blocker in this angle; running big C parsers on hostile files is.** The scientific C libraries are permissive, unlike Open CASCADE. HDF5 is 3-clause-BSD style, netCDF-C is BSD-3 style, ReadStat is MIT, and htslib is described as MIT/BSD. [V] But Debian's tracker lists 35, 27 and 17 CVE entries for `hdf5` in 2024, 2025 and 2026 (Debian triages them as "unimportant" because HDF5 is generally run on trusted data, an assumption a Quick Look extension cannot make), including heap overflows in the object-header code. ReadStat has OSS-Fuzz heap-overflow reports in its SAV and SAS7BDAT parsers. [V] Recommendation: own bounded Swift readers from the public specs for HDF5, Stata, SPSS and BGZF headers, matching how Parquet, Avro and Arrow were done (decision 018).
2. **The 2026 market has already filled several science niches with small, fast followers.** New or newly updated, all [VC] unless noted: Stats File Viewer (SAS/Stata/SPSS/R with Quick Look and data-grid thumbnails, free), Better Point Cloud Viewer (LAS/LAZ/E57, free), GIS Quick Viewer ($5.99) and GeoPreview (paid, 70 Product Hunt upvotes [V]) for GeoJSON/KML/GPX/GeoPackage/Shapefile, MIQ (free, open source, NIfTI/MGH/MIF/NRRD, 2026-05-08 [V]) plus FR[AI]ME and NIfTIViewQL, Burrete (MIT, PDB/mmCIF/SDF/MOL/XYZ, reviewed 2026-07-28 [V]), three DICOM Quick Look apps, and FITS apps; OmniPreview (a general Quick Look extension: free SQLite and GeoJSON, Pro NumPy, safetensors and GGUF) is a further general-purpose rival. None of these is in the 2026-10-05 landscape document.
3. **Still unserved as Quick Look, as far as I could find:** the HDF5 / netCDF / MAT family, genomics files (FASTA, FASTQ, GFF, BED, SAM, BAM headers), reference-manager exports (RIS, NBIB, EndNote), Newick trees, flow cytometry (FCS), EDF/BDF biosignals, PMTiles, FlatGeobuf, TopoJSON, GeoParquet metadata. Standalone apps exist for HDF5 (HDF5 Viewer, HighDeF), NetCDF (RasterScope $9.99) and EDF/BDF, but none of their descriptions claims a Quick Look extension. [V for descriptions]
4. **Two cross-cutting "lens" ideas fit the Safety Lens brand and no competitor has them.** An *integrity lens* ("this file looks truncated"): the SAM/BAM specification itself says the 28-byte BGZF end-of-file marker exists "so that unintended file truncation can be easily detected" [V], and other formats carry equivalents. A *personal-data lens*: EDF headers carry patient identification, name, sex and birth date in an 80-character field [V], and DICOM PS3.15 Annex E lists Patient's Name, Birth Date and ID as attributes a de-identified file must remove or replace [V]. See section 4.0.
5. **Suffix routing traps decide what can be registered.** `.vcf` is the system vCard type (`public.vcard`, conforms to `public.contact`), so genomic VCF cannot be claimed without taking another vendor's type. `.tif` is `public.tiff`: claiming it for GeoTIFF would take over every TIFF. `.dcm` (`org.nema.dicom`, conforms to `public.image`) and `.nii` (`gov.nih.nifti-1`) are declared by CoreTypes. Everything else I tested (`.h5 .hdf5 .nc .mat .rds .dta .sav .sas7bdat .xpt .orc .dbf .shp .gpkg .mbtiles .pmtiles .fgb .fa .fasta .fastq .bam .cram .pdb .cif .sdf .mol .xyz .edf .fits .fcs .ris .nbib .mlx .nb`) has no declaration on this Mac. [V, local]
6. **The Metal mesh renderer can carry molecules, with limits.** It draws indexed triangles only, and `GeometryLimits` caps a mesh at 100,000 faces and 1.5 million vertices [V, repo]. A ball-and-stick view of a small molecule or a ligand fits; a whole protein with sphere meshes does not (about 1,250 atoms at 80 triangles each). A protein needs a backbone tube plus capped atom counts, or sphere impostors, which would be a documented shared-contract change.
7. **Most candidates need no new presentation.** Outline tree, sortable table, Profile, facts header and findings cover HDF5, genomics, references, MAT/R, stats files, DICOM/EDF headers, ORC and FCS. New presentations are needed only for: a time-series line plot (EDF, FCS, spectra), a tree drawing (Newick), an image-slice view (NIfTI, FITS, DICOM pixels) and a point-sprite mode (LAS).
8. **Demand is real but its weight is uncertain.** Evidence is the pile of dead `.qlgenerator` plug-ins (QLNetcdf, HDF5QL, a MAT plug-in "not working in Mojave and later", QuickLookR, DTI-TK) and the 2026 launches in section 2. Counter-weight: much scientific data lives on clusters and is inspected in a terminal, so the Mac-local share of files is smaller than the user base suggests. [I]

## 4. Candidate sections

### 4.0 Cross-cutting insight layer: integrity and personal data

These are new typed finding kinds in the existing banner, so they cost one enum case, wording and strings per kind (decision 012), and apply across many of the candidates below.

**Integrity ("this file looks incomplete").** One finding kind with a typed reason, never source values.
- BGZF (BAM, `.fastq.gz`, `.vcf.gz`): the spec says an EOF marker block "should be written at the end of BGZF files, so that unintended file truncation can be easily detected", and that its absence "should trigger a warning or error". The check is "the last 28 bytes equal the marker". [V, spec section 4.1]
- HDF5: the superblock records an end-of-file address, so a file shorter than that address is truncated. [I from the spec's superblock section; confirm when implementing]
- netCDF classic: the record count and variable `begin` offsets versus file size. [I]
- FITS: size not a multiple of 2,880 bytes. [I from the FITS block rule]
- ORC and Parquet: missing or inconsistent tail magic and footer length (Parquet is handled today).
- Why it matters: interrupted `scp`/`rsync` or cloud downloads of multi-gigabyte files are routine, and most tools only fail later, deep in an analysis. [I]

**Personal data ("contains patient identifiers").**
- EDF/BDF: the 80-character local patient identification field and the recording identification and start date can identify the person. [V, spec]
- DICOM: Patient's Name (0010,0010), Birth Date (0010,0030), ID (0010,0020), Accession Number, Patient's Address and others are removed or replaced by the Basic Application Level Confidentiality Profile. [V, PS3.15 Annex E, 2026d] The Annex itself says using the profile "does not guarantee" removal of all identifying information, so wording must be "contains", never "is anonymised".
- Stats files: variable labels and names that look like names, emails, dates of birth, national IDs or addresses. The existing `SecretFieldPolicy` name patterns are the starting point; a new pattern group is needed. [I]
- Rules from AGENTS.md apply: the finding carries counts and attribute names, never values; displayed identifier values are concealed by default; no content thumbnails for medical or personal-data files.

**Provenance from inside the file.** A "where did this come from" facts strip using fields already in the file: `_NCProperties` and library versions (netCDF-4/HDF5), BAM `@PG` program lines and `@RG` read groups, FITS `CREATOR`/`INSTRUME`, DICOM Manufacturer and Software Versions, SPSS and Stata file labels and creation stamps. This differs from the earlier download-provenance idea because it needs no quarantine attribute. [I]

### 4.1 HDF5 family (HDF5, netCDF-4, Keras, AnnData, NWB, JLD2, MATLAB v7.3)

**Shows.** Facts header: format and superblock version, file size, user-block bytes, counts of groups, datasets and attributes, stored versus logical bytes (compression ratio), and a detected flavour: netCDF-4 (`_NCProperties`), Keras (`keras_version`/`backend` root attributes), AnnData, NWB (`nwb_version`), MATLAB v7.3 (a text user block, [I]). Modes: **Tree** (outline of groups and datasets, each row `float32 [3650 × 721 × 1440]`, chunk shape, filter chain, fill value, attributes expandable), **Table** (first rows of 1-D, 2-D and compound datasets, bounded), **Profile** (min, max, mean, missing on a clearly labelled sample), **Summary** (for CF netCDF: variables with `units` and `long_name`, decoded time coverage such as "days since 1850-01-01" to a date range, latitude/longitude extent), **Source** (an `ncdump -h`-style text copy).
**Insight layer beyond the raw file.** Compression and chunking facts ("chunk 1 KiB: unusually small, expect slow reads") [I]; Keras layer list and parameter count from `model_config` plus weight shapes [I]; AnnData `n_obs × n_vars`; external links and virtual datasets flagged as "stored in other files, not shown"; integrity finding; secret-like attribute names concealed.

**Demand.** Dead plug-ins: [QLNetcdf](https://github.com/tobeycarman/QLNetcdf) needs `ncdump` installed and targets old Xcode, and HDF5QL is listed in a [community plug-in list](https://github.com/haokaiyang/Mac-QuickLook) (both `.qlgenerator`, unsupported on macOS 15). [V via search results] 2026 apps: [HDF5 Viewer](https://apps.apple.com/us/app/hdf5-viewer-file-reader/id6798266211) (free, v1.0.12 on 2026-09-27, macOS 15+, tree, heatmaps, hyperslabs, S3 endpoints), [RasterScope](https://apps.apple.com/us/app/rasterscope-netcdf-viewer/id6807320389) ($9.99, 2026-09-22; NetCDF, GRIB, HDF), [HighDeF](https://github.com/twarge/highdef) (Apache-2.0, vendors HDF5 2.1.0). None describes a Quick Look extension. [VC]

**Route.**
- *Library option:* libhdf5 under its [BSD-3-style licence](https://github.com/HDFGroup/hdf5/blob/develop/LICENSE) (must reproduce notices; names The HDF Group, NCSA, UC LLNL and others) and netCDF-C under a [BSD-3-style COPYRIGHT](https://github.com/Unidata/netcdf-c/blob/main/COPYRIGHT). [V] Against it: Debian's [hdf5 tracker](https://security-tracker.debian.org/tracker/source-package/hdf5) shows 35, 27 and 17 CVE entries for 2024, 2025 and 2026, for example heap overflow in `H5T__bit_find` and `H5FL_arr_malloc`, and 2024-2025 entries in `H5O` encode/decode paths (CVE-2024-33874, CVE-2024-33875, CVE-2025-6816) [V via aggregators]. It also has a large CMake build, and I believe it can load filter plug-ins from disk [I]. Not recommended in-process; it would need a disposable XPC helper like the CAD worker.
- *Own reader (recommended):* the [HDF5 format specification v3.0](https://support.hdfgroup.org/documentation/hdf5/latest/_f_m_t3.html) (updated 2026-10-04) is public and covers superblock v0 to v3, v1/v2 B-trees, local and global heaps, fractal heap, v1/v2 object headers and all message types. [V] Precedent that a spec-only reader works: [jhdf](https://github.com/jamesmudd/jhdf) (Java, MIT, written from the spec), Rust `hdf5-pure` (superblock v0 to v3, object headers v1/v2, contiguous, chunked and compact storage), [jsfive](https://github.com/usnistgov/jsfive) (JavaScript, partial: no compound types). [V via search results] No pure-Swift reader turned up. [NV]
- *Staging:* **S0** netCDF classic (CDF-1/2): the header is a fixed grammar of dimension list, attribute list and variable list with `begin` offsets [V, [Unidata spec](https://docs.unidata.ucar.edu/netcdf-c/current/file_format_specifications.html)], days of work and bounded by construction. **S1** HDF5 tree with v0/v1 superblock, symbol-table groups and v1/v2 object headers (what h5py's default writes, [I]). **S2** link-message groups through fractal heap and v2 B-tree, dense attributes. **S3** first rows: contiguous, compact and chunked with v1 B-tree, deflate and shuffle. Anything else (lz4, zstd, blosc, virtual, region references) shows shape and dtype only.
- *Bounds:* a random-access source; a visited-address set (hard links can form cycles); caps on nodes (20,000, the outline limit), depth, continuation blocks and heap sizes; every length checked against the remaining file before allocation; nothing sized from a header value alone; work checkpoints for cancellation.

**Safety/privacy.** Read-only; no plug-in or filter loading; attribute and dataset names pass through the hidden-Unicode scanner and secret-field policy. Thumbnails: generic only.
**Risks/unknowns.** The complexity cliff is dense attribute storage and new-style groups (S2); HDF5 2.0 is changing the spec (the page carries 2.0 notes); MATLAB v7.3 tables and categoricals use opaque object encodings that I would show as "MATLAB object, not decoded". Mac-local share of such files is uncertain (finding 8).

### 4.2 Genomics: sequences, annotations and alignment headers

**Shows.**
- *FASTA/FASTQ (`.fa .fasta .fna .faa .fastq .fq`):* sequence count, total length, longest and shortest, **N50**, GC percent, N and ambiguity fraction, alphabet detection (DNA, RNA, protein), duplicate identifiers, line-width consistency. FASTQ adds read-length distribution, mean Phred quality per position (Profile mode), Phred offset guess (33 or 64), and paired-end naming hints. A compressed `.fastq.gz` or `.fa.gz` takes the existing GZIP route and sniffs the decompressed head. [I: the repository has bounded gzip/bzip2/xz readers; I did not check how the GZIP adapter presents content]
- *GFF3/GTF/BED:* feature counts by type, seqids and ranges, strand mix, malformed lines, `##gff-version`, coordinate-base reminders (BED 0-based, GFF 1-based).
- *SAM/BAM/CRAM header:* `@HD` sort order, `@SQ` reference names and lengths (is this GRCh38 or hg19? by contig-length match to known assemblies), `@RG` read groups, `@PG` program chain with command lines (which aligner and version). BAM needs only the first BGZF block(s). Counting reads needs a full scan, so it is not shown; the summary states "read count not computed".
- *GenBank (`.gb .gbk`):* locus, definition, organism, feature table outline.
- *Findings:* BGZF truncation (section 4.0); duplicate sequence IDs; non-ACGTN characters in DNA; Windows line endings; mixed Phred encodings; very long single-line sequences; command lines in `@PG` that contain tokens or paths are concealed by the existing secret policy.

**Demand.** I found no Quick Look app for FASTA, FASTQ, BAM or VCF in web searches. [V negative, limited by search] The only direct evidence of demand is the generic one: bioinformatics formats show a blank icon, and the BAM/CRAM header is what people otherwise get with `samtools view -H`. [I] Weakness: much of this work happens on clusters. I found no forum thread asking for it. **This is my least-evidenced lead.**

**Route.** Own Swift: text formats need no spec; BAM and BCF use the [SAM/BAM specification](https://samtools.github.io/hts-specs/SAMv1.pdf) (BGZF is gzip with an extra field; blocks are at most 64 KiB, so the first block yields the header). Apple's `Compression` framework or the repo's `BoundedDecompression.gzip` handles inflate. htslib is a permissive option ([MIT/BSD](https://github.com/samtools/htslib), depends only on zlib [V]) but is not needed for headers. CRAM headers use a different container structure (spec in hts-specs, not opened); treat CRAM as a stretch.
**Routing trap.** `.vcf` resolves to `public.vcard` (system, `CoreTypes`) [V, local]; `qlmanage -t` on a tiny genomic `.vcf` did not complete in 120 s on the research Mac, so I could not confirm what the system does (inconclusive). Do not register VCF; offer `.vcf.gz` and `.bcf` only through other routes if at all. Others (`.fa .fasta .fastq .bed .gff .sam .bam .cram .gb`) are undeclared. [V, local]
**Safety/privacy.** Genomic data is personal data. Sequence content is never placed in thumbnails; the preview shows statistics and a bounded excerpt of identifiers, not raw reads, by default. [I]
**Effort.** M: text stats S, BAM header S, GFF/BED S, tree view separate (4.9).

### 4.3 Molecular structures (PDB, mmCIF, SDF/MOL, XYZ)

**Shows.** A native Metal view: ball-and-stick for small molecules and ligands (element colours, bonds from `CONECT`, MOL bond blocks or distance), and for macromolecules a backbone tube coloured by chain or secondary structure (`HELIX`/`SHEET`) with ligands as ball-and-stick. For AlphaFold models colour by **pLDDT confidence**: AlphaFold stores pLDDT in the B-factor column with bands at 90, 70 and 50 [V via a PMC review summary]. Facts: atom, residue, chain and ligand counts, element composition and molecular formula, experimental method, resolution, unit cell (`CRYST1`), hydrogens present, alternate locations, residues missing from `SEQRES` versus `ATOM` (a common reason for "my loop is gone"), SDF record count with a 2-D depiction grid from the file's own coordinates.
**Demand and competition.** Burrete is a free MIT-licensed Quick Look extension for PDB, mmCIF, SDF, MOL, XYZ, trajectories and chemistry tables, built on Mol\* and RDKit, distributed from GitHub and Homebrew, macOS 12+ [V]; a [macinchem.org review dated 2026-07-28](https://macinchem.org/2026/07/28/review-of-burrete/) says macOS "does not provide QuickLook extensions for scientific file types" and records the provider-conflict problem (three UTI entries for `.sdf`). The repository is archived with development moved to a successor. [V] Differences SpacePane could offer: Mac App Store distribution (no Gatekeeper workaround), no web view (Mol\* is a JavaScript renderer, outside the project's native-only rule), secret and privacy pipeline, per-type switches, and the structure-quality findings. Not a clean field, so "Add", not "Lead".
**Route.** Own parsers. [wwPDB format v3.3](https://www.wwpdb.org/documentation/file-format-content/format33/v3.3.html) [V index page]; mmCIF/PDBx (IUCr, not opened); MOL/SDF is the CTfile format (not opened); XYZ is trivial. Licence: our own code. Mesh generation lives in `PreviewFormats/Geometry` next to `MeshBuilder`. Atom cap and level-of-detail: icospheres of 20 to 80 triangles, with total faces under `GeometryLimits.maximumFaces` (100,000 [V]); above about 1,000 atoms switch to backbone tube plus ligands, or add a sphere-impostor shader (a shared-contract change). Time-bounded neighbour search for bonds uses a spatial grid.
**Safety.** Parsers are text; coordinates validated finite; atoms, bonds, chains capped; multi-model NMR files show model 1 and a model count. Thumbnails: structure image is not personal data, so a content thumbnail is acceptable. [I]
**Effort.** M for small-molecule ball-and-stick plus facts; L with the backbone tube and quality findings.

### 4.4 Reference-manager exports (RIS, NBIB, EndNote tagged)

**Shows.** A reference list (authors, year, title, journal, DOI) as the existing BibTeX presentation does, a table mode, and a source mode. Findings: entries without DOI or year, repeated DOIs or near-identical titles (likely duplicates), mixed or unknown `TY` types, entries with unterminated records (no `ER`), and unusual non-spec tags. Facts: record count, year range, top journals.
**Why distinctive.** Broadest audience in this report (every student and academic). I found no Quick Look app for these formats. [V negative, limited by search] Unfold lists BibTeX only. [VC, landscape doc] Zotero notes RIS is "convenient for quick edits between export and import" and that the official RIS specification was last updated in 2001, so real-world files diverge. [V via search summary of [Zotero's data-formats page](https://www.zotero.org/support/dev/data_formats)] A preview that survives sloppy files is the value.
**Route.** Own line parser (`TAG  - value`, continuation lines, repeating tags), per the [gris RIS specification](https://gris.readthedocs.io/en/latest/specification.html). No dependency. EndNote XML and CSL-JSON share `.xml` and `.json`, which the product cannot claim; leave them to the XML and JSON adapters (recognising them by content would need a documented exception). [I]
**Safety.** Pure text; cap records and field lengths; the existing hidden-Unicode scan runs on titles and author fields.
**Effort.** S. **Risk:** none technical; demand is inferred.

### 4.5 MATLAB `.mat` (v5) and R data (`.rds .rda .RData`)

**Shows.** A `whos`-style table for `.mat`: variable name, class, size, bytes, complex/sparse flags; nested struct and cell fields in an outline; first values of small numeric arrays; a note for objects, function handles and MCOS opaque classes ("not decoded"). For R: a `str()`-style outline of lists, data frames (columns, types, factor levels), attributes and class, with first rows through the existing table.
**Demand.** A Quick Look MAT plug-in's own page says "Not working in Mojave and later versions" and a QuickLookR generator existed for R objects. [V via search results] Stats File Viewer covers R data frames only. [VC]
**Route.** MAT v5: tagged data elements with a 128-byte header; MathWorks documents it publicly (PDF, not opened); each variable is usually a zlib-compressed element, so inflate only as far as the matrix header (bounded). v7.3 is HDF5 (4.1). R serialization: XDR format version 2/3 with optional gzip/bzip2/xz (all decoders exist in the repo [V]); read structure without evaluating anything; closures and environments are shown by type only. Licence: own code; libmatio is BSD but not needed (licence not opened [NV]).
**Safety.** Never evaluate; cap nesting, element counts and decompressed bytes; reference cycles in R environments are cut by a visited set.
**Effort.** S to M. **Verdict.** Add.

### 4.6 Medical privacy lens: DICOM and EDF/BDF (NIfTI header optional)

**Shows.** *DICOM:* modality, study and series descriptions, dimensions, bit depth, transfer syntax (named), manufacturer and software, acquisition dates, and a **personal-data finding** listing the attribute *names* present (Patient's Name, Birth Date, ID, Accession Number, institution and physician names). Pixel display is left to macOS where it works (below); otherwise a generic image. *EDF/BDF:* recording start, duration, number of signals with labels, units and sampling rates, EDF+ annotations count, personal-data finding on the patient and recording fields, and a bounded line plot of the first seconds of a few channels (the plot is a new presentation).
**Native behaviour (local test).** macOS declares `org.nema.dicom` in CoreTypes (conforms to `public.image`, tags `.dcm .dicom 'DICM'`) [V, lsregister]. `qlmanage -t` produced a recognisable image thumbnail from a synthetic uncompressed 8-bit monochrome DICOM I wrote [V, one test]. I could not test compressed transfer syntaxes, and I assume ImageIO does not decode JPEG-lossless DICOM [I]. Registering `org.nema.dicom` would therefore compete with a working system path, so the evidenced gain must be the header facts and privacy finding, not the picture.
**Competition.** [DICOM Quicklook by OsiriX](https://apps.apple.com/us/app/dicom-quicklook-by-osirix/id1440819115) ($5.99, v1.5, 2025-02-22; its own text notes files contain patient name and ID), [DICOM Quick Look](https://apps.apple.com/us/app/dicom-quick-look/id6751081542) ($3.99, 2025-08-27) and [DICOM Data View](https://apps.apple.com/us/app/dicom-data-view/id1027545187) ($4.99, header only). [VC] None advertises a privacy check. EDF/BDF: a standalone [EDF & BDF Viewer](https://apps.apple.com/us/app/edf-bdf-viewer/id6801383472) (free, 2026-08-24) with no Quick Look claim found.
**Route.** DICOM Part 10: 128-byte preamble, `DICM`, explicit-VR little-endian elements; implicit VR and big-endian handled by transfer syntax; a curated tag-name table of a few hundred entries written from Part 6 rather than a bulk copy; skip pixel data by length. Sequences are depth-capped. EDF: fixed ASCII header, 256 bytes per signal ([spec, V](https://www.edfplus.info/specs/edf.html)); BDF is the 24-bit variant (spec not opened).
**Safety/privacy.** This is the highest-sensitivity category in the report. Findings carry attribute names and counts only; any displayed identifier is concealed by default with an explicit reveal like secrets; **no content thumbnails**; no network; no "anonymised" claims (PS3.15 says its profile "does not guarantee" removal). Burned-in pixel annotations cannot be detected reliably, so the wording must not imply the pixels are clean.
**Store-policy risk.** App Review guideline 1.4.1 gives closer review to medical apps "that could provide inaccurate data" or "could be used to diagnose or treat patients"; 5.1.3 treats health data as sensitive. [V, [guidelines](https://developer.apple.com/app-store/review/guidelines/)] Three DICOM Quick Look apps already ship, which suggests a viewer is acceptable, but state "not for diagnostic use" in copy and keep the feature to metadata. [I]
**Effort.** M (DICOM header and findings S to M; EDF header and plot M). **Verdict.** Add, header and privacy only.

### 4.7 Statistics packages (Stata, SPSS, SAS Transport, later SAS7BDAT)

**Shows.** Variables view (name, type, **variable label**, **value labels**, measurement level, declared missing values), a data table with value labels applied (toggle numbers or labels), and the existing **Profile** mode per column. Facts: observations, variables, file label and timestamp, software version that wrote it, character encoding. Findings: variables without labels (label coverage), value labels referencing missing codes, columns whose names or labels look personal, Stata strLs and very wide files noted.
**Competition.** [Stats File Viewer](https://apps.apple.com/us/app/stats-file-viewer/id6794522166) (free, 2026-09-28; "real data-grid thumbnails and Quick Look", Stata 113 to 119, SPSS in three layouts, XPT v5/v8, R data; Pro adds statistics and charts) is a direct, well-aimed competitor. [VC] StatDataViewer handles SAS only. [VC] SpacePane's edge would be Profile mode integration, personal-data findings, privacy of thumbnails (their thumbnails show real data with labels: for survey data this can expose respondents, [I]) and being part of an all-in-one app. This is a parity add, not a lead.
**Route.** Own Swift: Stata `.dta` is [documented by StataCorp](https://www.stata.com/help.cgi?dta) for third-party readers (format 118 in detail, 117/119/120/121 on linked pages) [V]. SPSS `.sav`: the PSPP system-file documentation (not opened; the fetch hit a rate limit). XPT v5: SAS technical note TS-140 (not opened); IBM-float conversion. SAS7BDAT has no official specification and relies on reverse engineering, so defer it. [I] ReadStat is [MIT](https://github.com/WizardMac/ReadStat) (reads SAS, Stata, SPSS; iconv, optional zlib; has libFuzzer targets and an OSS-Fuzz badge) [V], yet OSS-Fuzz has reported heap overflows in its SAV and SAS7BDAT parsers ([OSV-2025-408](https://osv.dev/vulnerability/OSV-2025-408), [OSV-2024-118](https://osv.dev/vulnerability/OSV-2024-118), [OSV-2020-327](https://osv.dev/vulnerability/OSV-2020-327)). [V via search results] Keep it out of process, or write the two formats.
**Effort.** M for `.dta` + `.sav`/`.zsav` + XPT v5.

### 4.8 Geo containers: PMTiles, MBTiles, GeoPackage, FlatGeobuf, GeoParquet, TopoJSON, Shapefile parts

**Shows.** Facts: CRS (EPSG code where stated), bounding box, feature or tile counts, geometry types, zoom range, tile format and compression, layer list. For PMTiles the first 127 bytes give version, bounds, min/max zoom, centre, tile type (MVT, PNG, JPEG, WebP, AVIF) and compression; metadata JSON gives name and attribution [V, spec]. The existing **offline plot** draws extents and, where cheap, geometry. Raster MBTiles/PMTiles could draw a low-zoom tile mosaic through ImageIO (PNG, JPEG, WebP decode natively [I]); vector tiles (MVT is protobuf) are a stretch.
- **GeoPackage and MBTiles** are SQLite files: layers from `gpkg_contents` and `geometry_columns`; for MBTiles the `metadata` rows and `tiles` table (TMS y-flip, `pbf` means gzip MVT [V, spec]). The SQLite inspection adapter exists; the new part is the domain facts. Conflict: the current SQLite adapter handles `.sqlite/.db`; the new suffixes are separate types.
- **FlatGeobuf:** an 8-byte magic then a FlatBuffers header (envelope, geometry type, columns, feature count, CRS) [V]. The repo's `FlatBuffersReader` already exists. BSD-2-Clause. Supported by GDAL 3.1+, QGIS 3.16+, PostGIS 3.2+. [V]
- **GeoParquet:** the `geo` key in the Parquet footer carries per-column encoding, geometry types, PROJJSON CRS and bbox; defaulting to OGC:CRS84 when absent [V]. The existing Parquet adapter reads the footer, so this is a facts addition on `.parquet`, with a geometry-column badge.
- **TopoJSON:** JSON with a transform and delta-encoded arcs; reuse the JSON reader and plot. Spec not opened.
- **Shapefile parts, honestly:** the extension sees one file. A `.shp` has the shape type and bounding box in its header [I, ESRI technical description, not opened] but **no CRS** (that is in the sibling `.prj`) and no attributes (sibling `.dbf`). The facts strip should state "CRS is stored in a separate .prj file, which Quick Look cannot read". A standalone `.dbf` is a complete table (dBase header, field descriptors, fixed-width records) and previews fully in Table mode. [I]
**Competition.** [GIS Quick Viewer](https://apps.apple.com/us/app/gis-quick-viewer/id6762661962) ($5.99, 2026-10-02; GeoJSON, KML, KMZ, GPX, GPKG, "SHP (limited support)"; interactive map, CRS, bounding box, feature counts, attribute table) and [GeoPreview](https://www.producthunt.com/products/geopreview) (paid, launched 2026, GeoJSON, Shapefile, GeoPackage, KML, GPX, LAS, `.gdb` folders) [VC]. OmniPreview offers GeoJSON. [VC] Their maps are likely basemap-based; SpacePane's rule is no network, so its plot has no basemap. [I] The unserved set is PMTiles, FlatGeobuf, MBTiles, TopoJSON and GeoParquet facts: I found no Quick Look extension for them; the only MBTiles precedent is a 2011 TileMill plug-in. [V negative, limited]
**Safety.** Existing GeoXML and JSON bounds apply; SQLite is read through the existing read-only inspection path; tile counts and blob sizes capped; PMTiles directories are small by design (header plus root directory under 16,384 bytes [V]).
**Effort.** M for the bundle (PMTiles S, FlatGeobuf S, GeoParquet S, GeoPackage and MBTiles M, TopoJSON S). **Verdict.** Add.

### 4.9 Phylogenetic trees (Newick, Nexus)

**Shows.** A drawn tree: rectangular cladogram or phylogram with branch lengths, optional radial layout, collapsed labels when over a threshold; facts (tips, internal nodes, rooted or not, max depth, support-value range, polytomies). Nexus shows the TAXA and TREES blocks. Findings: negative branch lengths, duplicate tip names, unbalanced parentheses.
**Demand.** No Quick Look app found; the only tree drawing app on the Mac list is [Phylogenetic Tree Draw](https://apps.apple.com/us/app/phylogenetic-tree-draw/id6443900345) ($4.99, last updated 2025-01-22, "plain, circular and radial trees in newick format"). [VC] Audience is small; the value is the visual delight.
**Route.** Own recursive-descent parser with an explicit depth cap and node cap; layout is O(n); drawn through the native Diagram canvas (a new tree layout is a small shared-contract addition). No dependency. **Effort.** S to M. **Verdict.** Add inside the genomics bundle, not alone.

### 4.10 FITS (revisit of the deferral)

Header cards (80 characters, 2,880-byte blocks) as key/value outline with WCS facts (object, observation date, exposure, filter, pixel scale, centre RA/Dec), plus a stretched 2-D image for simple uncompressed primary HDUs. Competitors exist: [FITS QuickLook Studio](https://apps.apple.com/us/app/fits-quicklook-studio/id6756870890) ($2.00, v11.2.8 on 2026-09-26, macOS 14+) with a guide app and LumaPair. [VC] Their listings do not state a Finder extension explicitly. [V] The format is public and the header reader is trivial; CFITSIO's licence I did not open [NV]. Image decoding (BITPIX 16/-32, BSCALE/BZERO, tile compression) is the larger work. **Verdict: Niche** — cheap, but competitors exist and the audience is small. Effort S to M.

### 4.11 NIfTI / MGH / NRRD

Strong, verified demand but already served. [MIQ](https://neurostars.org/t/macos-quick-look-extension-for-nifti-mgh-mif/36146) (free, open source, notarized, posted 2026-05-08, v1.0.0 on 2026-06-02; NIfTI-1/2, MGH/MGZ, MIF, NRRD; interactive orthogonal slices, 4D, optional thumbnail extension; macOS 15 and 26) [V]; FR[AI]ME (commercial, subscription for full previews) [VC via a [NeuroStars thread](https://neurostars.org/t/fr-ai-me-a-macos-quicklook-plugin-for-previewing-medical-images/35174)]; NIfTIViewQL (build from source, announced [2025-08-22](https://discuss.afni.nimh.nih.gov/t/new-macos-quick-look-nifti-preview-tool/9154)) [V]. The older DTI-TK plug-in no longer works on macOS 15, which created the gap. [V] MIQ claims `.gz` broadly for `.nii.gz`, which can conflict with other extensions (including SpacePane's own GZIP handling). [V via search summary] The 348-byte NIfTI-1 header is [documented](https://nifti.nimh.nih.gov/nifti-1/documentation/nifti1fields/) (the public-domain status I could not confirm from that page [NV]). **Verdict: Niche.** A fourth viewer adds little; a header-facts-only preview would not beat MIQ's slice view. Effort M.

### 4.12 Flow cytometry (FCS)

FCS 3.1 files carry a 58-byte header, a TEXT segment of keywords (`$PnN` short name, `$PnS` stain, `$TOT` events, date, cytometer) and a DATA segment. Preview: parameter table with the existing Profile statistics, event count, acquisition date, instrument, and a small histogram per channel (new). I found no Quick Look app; related tools are [FCSRead](https://github.com/gcs65/fcsread) (a Swift analysis app) and GenePattern's PreviewFCS (server-side). [V] Custom keywords may carry donor or patient identifiers, so a personal-data finding would apply. **Verdict: Niche.** Spec not opened [NV]. Effort M.

### 4.13 ORC (and Lance)

ORC's tail is a protobuf PostScript (compression kind, footer length, "ORC" magic) followed by a Footer with schema type tree, row count, stripes and column statistics, read backwards from the last byte [V, [ORC spec](https://orc.apache.org/specification/ORCv1/), Apache-2.0]. A protobuf reader is simpler than the existing Thrift reader and the Parquet presentation (schema table, summary, source) transfers directly; reading rows needs stripe decoding with RLEv2 and compression, so initial scope is schema and statistics. Not a science format as such (data engineering), but it was named in this angle. Lance and Zarr are directory or manifest stores whose Finder routing is uncertain. **Effort** S to M. **Verdict:** Add as a cheap sibling.

### 4.14 Notebooks beyond Jupyter

- `.mlx`: a zip package of XML parts; the existing ZIP reader and bounded XML parser could list code and text cells and cached outputs. [I, not verified against a sample]
- `.nb`: text with nested `Notebook[{Cell[...]}]` expressions; an outline of cell styles (Title, Section, Input, Output) without evaluating anything. Image outputs are embedded and large. [I]
- Pluto (`.jl`) and marimo (`.py`) are ordinary source with cell delimiters; today they preview as source. A Contents outline by cell would be an addition to the Julia and Python adapters rather than new types. I did not open the Pluto or marimo format documentation. [NV]
**Verdict: Niche.** Each is S. The notebook health check does not transfer (reactive notebooks have no execution counts).

### 4.15 LAS point clouds

[Better Point Cloud Viewer](https://apps.apple.com/us/app/better-point-cloud-viewer/id6790575828) (free, 2026-07-22, XYZ, PTS, PCD, PLY, LAS, LAZ, E57, "Quick Look previews and Finder thumbnails") and GeoPreview (LAS) already cover this. [VC] LAS header facts (point count, bounds, point format, CRS record presence, classification and return histograms) are cheap and need no new dependency; a sampled point cloud needs a point-sprite pass the mesh renderer lacks. LAZ needs LASzip, which is Apache-2.0 today per its project page, though older packages list LGPL and a FastAC licensing issue was raised in Debian ([search summary](https://laszip.org/)); I would not take it on. **Verdict: Niche.**

### 4.16 Spectra and mass spectrometry

JCAMP-DX is a labelled text format (`##TITLE=`, `##XYDATA=`) that would give a line plot and metadata. mzML is XML with base64 arrays, optionally zlib-compressed; run summary needs only the header, but an ion chromatogram needs array decoding and, for GB files, the trailing index. Demand and competitors: I found none for Quick Look; the Mac App Store list shows only small tools such as iMass. [V negative] Both need the line-plot presentation that does not exist. **Verdict: Niche.** Effort M.

## 5. Ruled out and why

- **GeoTIFF (and any `.tif` claim).** `.tif` resolves to `public.tiff`. A preview extension registered for it would receive every TIFF on the Mac and cannot decline to the system, so facts for GeoTIFF would degrade ordinary photo previews. The original motivation is real: in my test a synthetic 32-bit float single-band TIFF produced a near-blank thumbnail (298 bytes PNG) while an 8-bit one rendered, so elevation rasters are poorly served. [V, local, one synthetic file; real DEMs untested] Route would be the `.geotiff` or `.gtiff` suffixes only, which are rare. Rule out.
- **VCF (genomic).** The suffix belongs to the system vCard type (4.2). Rule out; handle `.vcf.gz` only if routed through GZIP.
- **GRIB and BUFR.** Needs WMO code tables and complex packing (JPEG 2000 or CCSDS); eccodes is far too large. RasterScope already reads GRIB as an app. [VC] Rule out.
- **ROOT (CERN).** TFile/TKey/streamer-info structure with zlib, LZ4, zstd and LZMA compression; the keys list is cheap but the audience (high-energy physics) is small and I found no demand. Not verified. Rule out for now.
- **SEG-Y, LAS well logs, TDMS.** Geophysics and LabVIEW audiences are small on macOS, and no demand evidence was found. Not verified. Rule out.
- **DuckDB `.duckdb`.** The on-disk catalog is not a stable public specification to my knowledge; the documentation fetch returned only a redirect [NV]. Reading tables would need `libduckdb` (MIT, but tens of megabytes and an in-process engine). Header-only version facts are possible but low value. Rule out.
- **Zarr and Lance.** Directory stores whose Finder routing for non-package folders is unknown; Zarr metadata is JSON that the folder preview could surface. Niche at best.
- **OSM PBF.** Protobuf with zlib blocks and a delta-coded dense-nodes scheme; large files and low "preview" value without a map. Rule out. OSM XML is plain XML (`.osm`) and could reuse the existing GeoXML reader if ever wanted. [I]
- **LAZ and E57.** Dependency (LASzip) and an existing free competitor. Rule out.
- **Whole-genome-scale operations.** Read counts in BAM, variant counts in large VCF, and any statistic that needs a full scan of a multi-gigabyte file are out of the Quick Look time budget; show "not computed" instead.
- **Proprietary instrument and clinical formats** (Thermo `.raw`, DICOM-RT, vendor MRI formats): no public specification I could open; no demand evidence.
